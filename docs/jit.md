# The block translator and emitter

How AArch64 blocks are translated, run, and written out as wasm.

Section headings are paths under `crates/switch-core/src/cpu/jit/`; a heading that starts with `crates/`, `tools/` or `web/` is from the repository root.

## `mod.rs`

- Translation removes decode, not dispatch: a block is a run of pre-decoded `ir::Op`s cached by entry address.
- A block is compiled to wasm after `HOT` entries, together with the warm blocks it branches to (its region). Each region is one module, compiled and installed on its own by `exec.rs`'s `install`.
- Emitted modules import the core's linear memory, so guest registers and NZCV are plain loads at fixed `Cpu` offsets. Accesses the page table cannot answer alone go back to the host, mirroring the interpreter's split.
- Only the browser build compiles emitted code; host builds translate and interpret. `emit_difftest` and `emit_selftest` cover emitted code under V8.
- Fidelity: ops call the interpreter's helpers; unknown forms become `Op::Interpret`. Mid-block `Interpret` is allowed only for instructions that cannot move the PC except to the next one: the branch and exception group is a terminator, the `0xD5` system group (hints, barriers, `MRS`/`MSR`, cache maintenance) is not.
- Staleness: a block lists every page it read (it can span pages through followed `B`s and page boundaries); `Memory` reports stores to translated pages and `jit_block_at` drops their blocks before each lookup. The process's shared `Memory` keeps one dirty-page list per core (`dirty_code_pages(core)`), so each core's cache drops its own translations; a list that overflows reports every translation stale.
- Caches are per core and per process: `Cpu::jit` holds the running process's blocks, and `enter_process` swaps it with that process's entry in `parked_jits`. `forget_translations` drops an ended process's cache, `jit_flush` also clears the parked ones, and `run_jit` drops its held block when the pid changes, so one process's code is never linked to another's.

## `decode.rs`

- Blocks continue through conditional branches (`B.cond`, `CBZ/CBNZ`, `TBZ/TBNZ`) as `ir::Exit`s; only an always-leaving instruction ends a block. On hbmenu this took the average block from 7 to 13 instructions, and it puts `CMP`+`B.cond` in one block so they can fuse.
- `MAX_BLOCK_OPS` is not the binding limit: raising it to 160 moved hbmenu's block entries by 0.2%, since indirect branches and returns end blocks.
- `translates()` gives an exact, target-independent answer; timing two engines on a desktop is not evidence about the browser.
- Direct `B`s are followed (fewer entries, about 1% of a wasm frame). Following `BL` copies the callee into every call site and cost 4% more than it saved. A jump in the last slot is not followed, since the block would only move the PC.
- PLT stub folding: otherwise a cross-module call costs two block transitions and four dispatches (500K of 1.78M block entries on Just Dance 2019, whose `nn::` lives in the sdk module). The stub's four words must be on one page, which the block lists. The stub code is assumed fixed, but the GOT slot is loaded on every call so rebinding imports still works, and an unreadable slot falls back to running the stub so the fault lands on its `ldr`.
- The `0xD5` group goes through `decode_system`, not a `Nop` shortcut: the shortcut made `CLREX` a hint while the interpreter cleared the monitor.

## `ir.rs`

- Size budgets (asserted in tests): `Op` is 16 bytes (one 64-bit payload plus tag), so `Op::MovK` stores shift+halfword instead of mask+value; `Exit` is 16 bytes with its own tag byte (a niche-hidden tag cost several instructions per taken exit), so `Exit::CmpImm` keeps the encoded immediate instead of the inverted `u64`; `Branch` is 24 bytes, its precomputed span fitting in existing padding.
- Specialized variants (`Load64`, `PairLoad64`, `PairStore64` etc.) exist because the general form dispatched twice (op, then access) and V8 mispredicted each indirect jump separately.
- Block links (`LINKS` successors, most recent first) are an inline cache. On a Just Dance 2019 frame, 1 slot linked 73% of entries and 4 slots 82.5%; 8 added nothing, the rest being `RET`s from functions with many callers.
- Links are `Weak`, so a block invalidated by a guest store to its page is unreachable through stale links without a separate invalidation pass.
- Blocks start cold and are counted before emission: most translated blocks run once or twice, so emitting them costs more than interpreting them.
- `Block::new` trims `ops`/`words`, which the translator sizes for the longest block; untrimmed, a full cache was about 80 MiB of mostly empty heap.
- Dropping a block frees its function-table slot and clears its region members; otherwise the table grows by one slot per block ever compiled.

## `exec.rs`

- `HOT` threshold: each region is its own wasm module with its own V8 code region, so entering thousands of scattered modules through one indirect call stalls more than their bodies save. Measured on Just Dance 2019 before regions (one module per block): a threshold of 16 emitted 7,990 blocks and ran 4% slower than pure interpretation; 512 emitted 1,185, covered 97% of the same entries and beat the interpreter. With regions, the cost is compiling: V8 compiles a region lazily, on its first call, on the core's own thread (a median 3.7 ms for a 24 KB module, since every exit to the epilogue merges ~40 live register locals), then again in TurboFan on background threads (a median 66 ms). Just Dance 2023's boot compiled about 100 regions a second at 512, more than 60% of the core's thread, and most of that code ran a few thousand times. At 32768, measured in the browser over three boots each: Just Dance 2023 reached 1,000 frames at 67 s instead of 177 s, Just Dance 2019 its title screen at 90 s instead of 150 s, Minecraft its title screen at 135 s instead of 175 s, and the steady menus (Just Dance 2023 at its 30 fps cap, Minecraft at 42 to 49 fps) did not slow. Compiling asynchronously does not help: lazy compilation still compiles on the first call's thread.
- `MAX_MISSES`: a hand-back at instruction zero retires nothing. One or two are normal (first touch of a soft-mapped page), but a block whose first instruction always needs the slow path (a store to a watched page in a loop) loses its compiled form for good. Any progress resets the count.
- The step budget is exact: blocks are a cache, not a unit of execution. A compiled block that does not fit the remaining budget is interpreted that visit. A budget that splits a fused exit runs the part that fits, so progress is never zero (otherwise `run_jit` spins).
- `exec_block` is inlined into `run_jit`: as a call, each entry paid a 384-byte V8 frame (about 5% of a wasm frame) with no change in host cycles; host and wasm timings are not related by a constant.
- `Here` (stretch start) is carried instead of a per-op address, which cost a reload, add and spill on every op under V8.
- The held block and its links matter: a block boundary falls every ~6 instructions on a retail frame, and nearly all lead where they led before.
- Chain fuel is where `run_jit` would stop following blocks anyway (the budget less `MAX_WHOLE`, the end of the time slice, the next timed-wait sweep), so a chain retires exactly what entering each block from here would. Branches inside a region and jumps between regions both charge it. On return, the left blocks' clock and steps (the fuel spent) are added and the block that answered is settled as if entered directly; one that stopped at its first instruction gets `pc` set to its start and is left for the next visit.
- Regions: when a block turns hot, the cached blocks its known branches reach (conditional targets, `B`, the fall-through of a cut block, a `BL`'s target and return point, a register branch's linked successors) that have run `REGION_WARM` times or are already compiled are emitted with it, breadth-first, up to `MAX_REGION_BLOCKS`. A member that refuses is dropped and the region re-emitted; one too long truncates it. The head's `members` holds them, and `run`'s answer indexes it from 1.
- Only the block a region or chain stops in records trail runs; blocks left through a branch inside a region or a jump to another region do not.
- Folded PLT calls are written terminators: the stub's four instructions count in `whole`, so `MAX_WHOLE` reserves them, and `finish_emitted` records the stub as its own run.
- A JIT-against-interpreter lockstep cannot run far: the interpreter preempts at any instruction and the JIT only between blocks, so the first time-slice expiry inside a block already switches threads differently. Two JIT builds that chain differently diverge the same way. Just Dance 2017 stalls around frame 250 under some such schedules (a priority-43 thread parsing JSON while main waits on a lock) and not others, so a stall that a one-instruction `TIME_SLICE` change makes disappear is a scheduling problem, not an emitter bug.
- Clock, step counter, trail and `pc` are settled at block end or fault, not per instruction. The clock is retired after the terminator, as in `step_inner`: retiring early gave every SVC a tick the interpreter had not spent (a homebrew title diverged by one cycle through a sleep deadline).
- A parking syscall rewinds pc onto its own `svc`, so only then is an `svc` a block entry; `Term::Svc` retires the `svc` before dispatch so a thread switch resumes the outgoing thread after it.
- `take_exit` uses one match for all branch kinds; checking "followed?" first cost 6% of a wasm frame. `exec_op`, `take_exit`, `apply_compare` and `exec_term` take references: by value, the compiler loads the 16-byte `Op` and hoists every field's extraction above the jump table (9 loads and 6 shifts per dispatch).
- `load_store_fast` makes no calls: V8 spills values live across a call at their definition whether or not the call happens (a load paid six stores). The slow path restarts the instruction from scratch, which works because the fast path commits nothing until it finishes. The PLT-stub fold follows the same rule.
- `BIC`/`ORN`/`EON` invert the shifted operand, not the register (as dynarmic and the ARM ARM do).

## `cache.rs`

- Two-generation cache: when `blocks` reaches `MAX_BLOCKS` it becomes `older`, and the previous `older` is dropped. `Jit::get` moves (not copies) blocks found in `older` back into `blocks`, so live code survives any number of rotations and the generations stay disjoint (ceiling 2 * `MAX_BLOCKS`). A single-generation flush made Just Dance 2019 hit the cap during boot and retranslate everything, losing all links.
- `lookup` is a direct-mapped hint (`LOOKUP_SLOTS`) checked against the block's entry address.
- `by_page` lists a block under every page it read. Dropping it through one page leaves stale entries under the others, which can only cause spurious retranslation, never a stale block. Rotation rebuilds it from the surviving generation.
- Invalidation must check both generations, since `get` still reaches `older`. Every drop clears the lookup hints so no hint outlives its block.
- Diagnostics: `linked / executed` is the link hit rate; `interpreted` against the run's step count is the share not translated; `entered_emitted / executed` is the emitter's useful coverage; `chained` counts jumps between compiled regions. `retired_emitted / retired` is the share of instructions compiled code ran rather than the op walk, and `dropped` counts compiled blocks given up after `MAX_MISSES` hand-backs at their first instruction. Like the rest, they count one core's `Cpu`; the page shows the main core's.
- The chain table maps entry addresses to compiled entries for emitted code, direct-mapped, with `CHAIN_SLOTS` slots. Small tables lose most jumps to collisions: with about 10K compiled blocks on a Minecraft frame, 4,096 slots chained 32% of compiled entries. A vacant slot holds an address that hashes to another slot, so no lookup matches it.
- A region's head is also listed under its members' pages (`cover`, and the rotation rebuild through `region_pages`), so a store to any of them drops the region. Every block that leaves the cache drops its compiled form and its member list, since heads may hold each other and the `Rc` cycle would otherwise outlive the cache. A member that leaves the cache while its region lives keeps only its translation, which the region's answers still name.
- A block leaves the chain table when it leaves the cache (invalidation, rotation, clear) or loses its compiled form, before its function-table slot can be reused. A block compiled after it left the cache is never chained to.

## `emit.rs`

- The file holds the layout, constants, the `Emitter` state and the entry points. Its `impl Emitter` is split by concern into `emit/flow.rs` (block walk, exits, terminators, prologue and epilogue), `emit/alu.rs` (arithmetic, flags, shifts, multiplies), `emit/mem.rs` (page checks, loads, stores, the exclusive monitor) and `emit/dispatch.rs` (the per-instruction `op`), beside the `simd`, `fp` and `a32*` writers.
- The `Cpu` address is a parameter, not baked in: blocks belong to guest addresses and guest threads share one `Cpu`, but tests build many, and a baked pointer would address a freed one. Since the module imports host memory, nothing is copied in or out.
- Everything the translator resolved (width, shift type and distance, extension, condition) is a constant in emitted code; a condition becomes its `CONDITION_MASKS` row shifted by NZCV.
- Coverage is a performance question: a refused block runs on the interpreter, so ops are added one at a time behind `emit_difftest`. `Refused::Op` carries the instruction word that `examples/emit_difftest.rs` ranks; `examples/emit_selftest.rs` sweeps the encoding space with `emits()`.
- Guest access is a two-level page-table walk: the 64-bit address (`L_ADDR64`) picks a 2 MiB block from the top-level table, the low 32 bits (`L_ADDR`) the page within it and the offset within the page. Soft regions, protection, watchpoints and cache reports are not on this path because `Memory::peek`/`poke` already split off the part the page table answers; emitted code makes their checks in their order. A top-level entry is never null (untouched blocks share one empty block), so only the page entry is tested; bits above the 39-bit space are dropped, as `Memory` drops them.
- Table entries at both levels are `AtomicPtr`s, a page entry null when unmapped, which is how emitted code tests unmapped pages; they are 4 bytes on wasm32 (asserted at compile time). A block is `#[repr(C)]`, so its page entries and cached-pages bitmap are at fixed offsets (`Layout::block_pages`, `block_watched`).
- Write-protected pages are set in the watched-page bitmap (`mark_readonly`, and again after a host write reports them), so a store tests one bit for protection and cached contents alike. The bitmap lives in the block the store already walked to, so the test is one load more.
- Addresses enter `L_ADDR64`/`L_ADDR` only through `set_addr64` (A64) and `set_addr32` (A32, and literals and GOT slots below 4 GiB), so the two never disagree. Watchpoints and the exclusive monitor compare the whole 64-bit address; the monitor's `addr` is a `u64`.
- A register branch to a target above 4 GiB leaves the region before writing anything, and the interpreter faults on it (`Cpu::branch_target`): code is only loaded below 4 GiB, and the pc is a `u32`.
- Watchpoint tests are emitted only while one is armed: `run_jit` drops compiled code when that changes. Dropping them and the envelope test made a straight-line loop of loads and stores about 1.8 times faster.
- `LDXR`/`STXR` (one register, with the acquire and release forms) are emitted over the monitor in `Cpu::exclusive`, a `#[repr(C)]` struct the code reads and writes in place. The store takes the monitor whatever happens and, when it was armed at that address, swaps with a wasm `cmpxchg`; a misaligned address hands back, since a wasm atomic would trap. The pairs use the same monitor: `LDXP` loads both halves and arms it (the word form as one doubleword), and the word-form `STXP` swaps that doubleword with one `cmpxchg`. Wasm has no 16-byte atomic, so the doubleword form compares and writes under `Memory::pair_lock`, the byte the interpreter's `compare_exchange_pair` also takes (`Layout::pair_lock`, spun on with an 8-bit `cmpxchg`); it hands back before spending the monitor when a read watchpoint covers the pair, since the interpreter's compare reads it.
- An access declines before writing any register, so the interpreter resumes the stopped instruction whole, by translating at that address rather than re-entering part-way. `defers()` is derived from the emitter (emit under two counts, compare bodies) so it cannot drift from the arms; difftests use it to know which `run` answer is right.
- `LEFT` is needed rather than inferred from a short count because a branch on the last body instruction retires everything yet must not fall into the terminator. A taken branch counts as retired so a block always makes progress. `B`, `BL`, `BR`, `BLR`, `RET` and PLT-folded calls are emitted and leave with `LEFT` (`writes_term`); `SVC` and the rest stay with `exec_term`.
- A region is one function: a `loop` whose head dispatches on a block index with `br_table`, each block falling into the next when that is where it goes. Forward branches inside it are plain `br`s to the target's label; only backward ones go through the `br_table`, an indirect jump shared by every edge.
- A register branch (`BR`, `BLR`, `RET`, a folded PLT call) compares its target with the region's blocks among its linked successors and, for a `RET`, with the return points of the region's calls, and branches inside on a match. Without this every call and return left the region: a guest loop doing one virtual call per byte ran at 0.48G instructions/s, and 1.85G with it. Every exit stores its answer and branches to one epilogue, so the stores are written once. `run`'s answer is the stopping block's retired count, its index above `MEMBER_SHIFT`, and `LEFT`; a lone block answers as before, which keeps the difftest harnesses unchanged.
- Guest registers, NZCV and the A64 vector registers live in locals (`v128` ones for `V<n>`, through `vget`/`vset`): the prologue loads every slot the region touches, the epilogue stores every slot it writes. Locals are allocated per slot on first use; declaring all 34 up front made every entry pay V8's zero-initialization and ran about a third slower. The zero register reads as a constant and the discard slot is never stored. A32 blocks keep only the core registers in locals; their VFP and NEON read and write `vregs` in memory.
- `Layout` offsets for registers, NZCV, FPSR, `pc`, fuel and vector registers are `offset_of!` into `Cpu`. Guest memory state is not in `Cpu`: `Layout.memory` is where the core's `AddressSpace` keeps its `*const Memory` (`offset_of!(Cpu, mem) + AddressSpace::MEMORY_AT`), and the remaining fields are offsets into `Memory` (`mem::Offsets::OF_MEMORY`).
- The top-level table pointer changes only in host code, so the prologue loads the `Memory` address once and then the pointer into an `L_ENV` local, rather than per access. Watchpoint bounds are `u64`s, wider than an `L_ENV` local, and are loaded where tested, only in regions emitted while one is armed.
- Chained regions leave a taken exit or written terminator with `return_call_indirect` from the epilogue into the target's compiled region, when the chain table has it and the fuel covers what the stopping block retired. The jump stores the fuel, counts itself and records the target. A tail call keeps the native stack flat however long the chain, and costs little: in real code the cost is what stays interpreted.
- `CLZ`/`RBIT`/`REV*` are wasm `clz` and mask-and-shift swaps, and `MRS` of `TPIDR_EL0`, `TPIDRRO_EL0` and the constant registers is a load from `Cpu`. Scalar FMIN/FMAX/FMINNM/FMAXNM select the NaN operand by hand, since wasm's `min` and `max` canonicalise it, and FCCMP selects between the comparison's flags and its immediate.
- Advanced SIMD (`emit/simd.rs`) is written as SIMD128, decoded from the instruction word: three-same (including FADD/FSUB/FMUL/FABD and the float compares), three-different (long and wide), shift by immediate including the narrowing shifts, two-register misc (narrowing, ABS/NEG, FABS/FNEG, REV16/32/64, CNT/NOT), FMUL by element, permutes, EXT, DUP/INS/SMOV/UMOV, MOVI/MVNI/ORR/BIC and FMOV immediate, scalar SCVTF/UCVTF, FCVT{N,P,M,Z}{S,U} and FABD, and SIMD&FP loads and stores (LDR/STR of B to Q, S, D and Q pairs, LD1/ST1 of one lane, LD1R, and LD1 to LD4 and ST1 to ST4 of whole registers, which are lane loads and stores at the interleaved offsets after one page check). Rounding shifts are `(x >> s) + ((x >> (s - 1)) & 1)`, which never leaves the lane. Wasm's narrows treat their input as signed, which is right for the signed-source forms and for an unsigned source already shifted right by at least one; UQXTN clamps with `min_u` first. It more than doubled the instruction rate on Just Dance 2017's VP8 menus.
- Scalar floating point (`emit/fp.rs`) is wasm `f32`/`f64` where the interpreter's arm is IEEE arithmetic. Single-precision FMADD and its variants copy the interpreter's `f32::mul_add`, which is libm's `fmaf` on wasm32: the sum in double precision, nudged one unit when it lies exactly halfway between two singles but is inexact. Double FMADD and its variants are emulated when every operand is finite and either zero or between 2^-300 and 2^300 in magnitude: a zero factor or addend is one ordinary operation; otherwise the exact product (Veltkamp split, Dekker's product) and the exact sum with the addend (two-sum) are combined by rounding to odd (Boldo and Melquiond) before the final add, so the result is rounded once, as `f64::mul_add` is. Anything else (an infinity or a NaN, an exponent outside that range, a subnormal) hands back. FRINTA is the truncation moved a unit away from zero when the dropped fraction is at least half; FRINTX and FRINTI read `Layout::fpcr` for the rounding mode. Float-to-integer converts, FDIV and FSQRT set FPSR's cumulative bits as the interpreter does, so `Layout` carries FPSR and both difftests seed and compare it.
- The clock (`MRS` of `CNTPCT_EL0`/`CNTVCT_EL0`) must read what the interpreter would, but `cycles` is settled only when a chain returns. `enter_emitted` stores `Chain::origin`, `cycles` plus the starting fuel, so the clock at a block's op `i` is `origin - fuel + i`: the fuel already counts every block left through a branch or jump. Other cores read core 0's published clock through `Cpu::clock_at`, a raw pointer kept beside the `Arc` (`share_clock` sets both). Ticks are `q * N + (r * N) / D` for `cycles = q * D + r`, which equals the interpreter's 128-bit product for every `u64`; `emit_selftest` seeds the clocks where the two would part.
- wasm vs A64: 32-bit variable shifts must mask the distance to 32 themselves; div by zero and `i64::MIN / -1` trap in wasm and are guarded with real branches (not `select`, which evaluates both arms); a 32-bit signed division cannot overflow since operands are sign-extended. There are no 128-bit integers, so `SMULH`/`UMULH` are built from 32-bit partial products. In `add_carry`, a 32-bit op's carry is bit 32 of the untruncated sum, so only 64-bit ops need the explicit carry chain.
- Past bug: a 32-bit `CCMN` read Rm unnarrowed, carrying its top half into the bit-32 carry; `CCMP` hid it because inverting masks again.
- Fusing: a fused compare retires two instructions; misreporting would make the interpreter re-run the compare with stale operands. An exit the walk never reaches would make the guarded instructions run unconditionally, so such blocks are refused (`Refused::ControlFlow`).

## `wasm.rs`

- Hand-written because `switch-core` has no dependencies and the encoder must compile to wasm and stay small (it runs for every region compiled). No globals or multi-memory: unneeded ops would be untestable dead code. SIMD opcodes go through `simd()`, with the numbers named where they are used.
- Signed and unsigned LEB128 agree only up to 63; a constant 64 written unsigned decodes as -64 and still validates, hence separate names and a test.
- Load/store alignment is a hint the engine may rely on, so it must not exceed real alignment; guest addresses promise none, so callers pass it explicitly.
- The module imports the emulator's memory as `e`.`m` with a minimum of zero pages, since the host has sized it. When the core is built with atomics the import is declared shared with a 65,536-page maximum, because a shared memory only matches an import that says so.

## `host.rs`

- Compiled regions are called through the embedder's function table (an `Entry` is a table index on wasm32, a function address on host), not a JS import: a host call per entry would cost more than the dispatch the JIT removes. The JS boundary is crossed only at install time.
- `switch-core` cannot reach `WebAssembly.Module` (zero dependencies), so the embedder supplies `install`/`release` and whether the engine has tail calls and SIMD128.
- `install` failure is never an error: the block stays on the interpreter. The first `set_jit_host` wins because entries from one host mean nothing to another.

## `a32/`

- The A32 translator is a separate, smaller pipeline: `decode.rs` turns each ARM word into an `a32::Op` (pre-decoded fields, the condition on every op), `exec.rs` runs it, and `Jit::a32` caches the blocks. `run_translated` picks `run_jit` or `run_a32_jit` by the running thread's mode, and each returns when the mode changes.
- A block ends at the first instruction that can write the PC (`B`, `BL`, `BX`, `SVC`, a data-processing or load destination of `r15`, `LDM` with `pc`, `BLX`), as `a32::Term`. Branches are not followed, and a skipped conditional terminator falls through to the next address.
- Ops call the interpreter's helpers (`a32_alu`, `a32_single`, `a32_extra`, `a32_block_transfer`, `shift_c`), so semantics are shared. `self.pc` is set before every op, which makes `r15` reads and the helpers' own `pc + 4` correct.
- `SXT`/`UXT` of a byte, halfword or `B16`, `BFI`/`BFC`, `MUL`, `MLA`, `MLS`, the long multiplies (not `UMAAL`), `LDREX`/`STREX` of a word, halfword or byte and the `MRC` reads of `TPIDRURO`/`TPIDRURW` are ops. `BLX` through a register, `LDR pc` and `LDM` with `pc` in the list are terminators with their own kinds. Anything else (the other media instructions, `UMAAL`, VFP, NEON, other coprocessor access, `MRS`/`MSR`, `LDREXD`, acquire/release) is `Kind::Interpret`, which calls `execute_a32` and so tests the condition itself; one of those that can write the PC is `TermKind::Interpret`.
- Invalidation, per-process caches and the retire/clock accounting are the A64 path's: `Jit::invalidate` and `clear` drop A32 blocks too.
- Hot blocks are emitted (`emit/a32.rs`) as the leading ops the emitter can write, then a stop; `exec` carries on from the count with the op walk, so an op with no writer (other media, `LDREXD`, `MRS`/`MSR`, barriers, the NEON forms `a32_neon.rs` refuses) ends the compiled part of its block, not the block's chance. A block written whole ends in a `B`, `BL`, `BX`, `BLX` register, `LDR pc` or `LDM` with `pc` that leaves with `pc` set and, where the engine has tail calls, jumps into the next compiled block through the same chain table as A64. `SVC`, an interpreted terminator and a branch to an odd address (a switch to Thumb) are left to `exec`.
- Every memory access checks the page table first and hands the instruction back, as in A64. `LDM` and `STM` check all their addresses before any access, so a hand-back leaves no register or word half done; an `LDM` that loads its own base is not written.
- The extra loads (`LDRH` and friends) write the base last, and a single load into its own base keeps the loaded value: the emitter follows the interpreter in each.
- VFP and Advanced SIMD stay `Kind::Interpret` in the IR; the emitter decodes the word itself (`emit/a32_vfp.rs`, `emit/a32_neon.rs`), as it does `SBFX`/`UBFX` in `emit/a32.rs`. VFP mirrors `cpu/a32/vfp.rs`: arithmetic in `f64`, a single narrowed on the way out, `D<n>`/`S<n>` read straight from the `vregs` bytes, FPSCR as `fpscr_nzcv`, `fpcr` and `fpsr` (so `Layout` carries `fpscr_nzcv`). Fused multiply-adds, the ARMv8 unconditional forms (except NEON `VMAXNM.F32`/`VMINNM.F32`, which both engines misdecode as `VRECPS`/`VRSQRTS`), `VMAX.F32` and `VMIN.F32` (Rust's `min`/`max` drop a NaN, wasm's keep it), the halving, rounding and saturating NEON forms (except `VRHADD.U8`/`.U16`, which is `avgr_u`, and 8- and 16-bit `VQADD`/`VQSUB`), polynomial multiplies, table lookups and `VSWP`/`VTRN`/`VUZP`/`VZIP` stay on the interpreter. A NEON D operand is loaded with `load64_zero` and stored as its low half.
- `VLDM`/`VSTM`/`VLDn`/`VSTn` check their whole range once, so a hand-back leaves nothing half moved. `LDRD`/`STRD` are written for an even `Rt` below `r14` whose base is not written back over the pair.
- T32 has no translation: a Thumb thread runs in the interpreter, and the A32 JIT leaves the block loop when `thumb` is set.

## `crates/switch-wasm/src/jit.rs`

- Regions go into this instance's own function table and are entered with `call_indirect` (a Rust fn pointer on wasm32 is a table index). Tables are per instance, so with several workers on one memory each has its own table and its own free list (`FREE` is thread-local).
- Synchronous `WebAssembly.Module` is required (regions are compiled inside a run slice); windows refuse large modules synchronously but workers allow any size.
- Freed slots are recycled, since the cache drops blocks constantly. A freed slot still points at its old function (there is no null function entry), so memory is bounded by the peak number installed. Slot 0 is the linker's null and means "not installed"; it must never be handed out. A failed compile returns 0 and the block stays interpreted.
- `attach` runs from `switch_init` right after instantiation. It probes tail calls (`tail_call_probe`) and SIMD128 (`simd_probe`) with `WebAssembly.validate`: without tail calls regions are emitted unchained, without SIMD128 Advanced SIMD stays interpreted. Every module is offered the function table as `e`.`t`; unchained ones do not import it.

## `crates/switch-wasm/src/heap.rs`

- The global allocator is dlmalloc with a 4 MiB growth granularity instead of 64 KiB. Guest RAM is backed per 4 KiB page on first touch, so asset loading caused hundreds of `memory.grow`s (about 500 for 32 MiB in Just Dance 2019), and each grow cost V8 time per instance importing the memory (every compiled block): 0.4 s of `SetInstanceMemory` over 60 frames, measured on the unshared build. Unused grown memory is not backed until written.
- The allocator sits behind a spin lock (`Heap::with`), since core workers instantiate over the same shared memory and all allocate.

## `tools/jit_wasm_check.mjs`

- Covers what host tests cannot: emitted blocks use wasm32 field offsets, 4-byte page-table entries (8 on the host), and function-table slots as entry points. A block is compiled after `HOT` visits, so a program's `steps` must give its loop more trips than that. Each program runs with the translator on and off and must agree on every register and the clock; the `emitted`/`enteredEmitted` stats guard against a build that silently interprets everything, and `expect` against a run that faulted immediately.
- A64 programs cover plain arithmetic, a store/load through the emitted page-table walk, a store, load and exclusive pair above 4 GiB, a barrier and a store-release read back by a load-acquire, a fused `cmp`+`b.ne` back edge, a `tbz` branching somewhere other than the block start, clock reads summed across blocks that branch into each other, a compare's deferred flags read in a block a `cbz` branches to (which fails if `edge` stops building them), and `bl`/`blr`/`ret` calls. A32 programs cover data processing with flags and shifts, loads and stores (write-back, halfwords, multiples), calls and returns, exclusives with thread-pointer reads, `BLX` register, `LDR pc` and `POP {pc}`, and a conditional back edge.
- It also fails unless some compiled block jumped into another, since a build without tail calls would pass every comparison unchained.

## `tools/emit_difftest.mjs`

- Split from the Rust half because `switch-core` has no dependencies and the host has no wasm engine, while the interpreter reference lives in Rust. Cases are `run(state) -> i32` modules over a bare `WebAssembly.Memory` at manifest-named offsets, so the tool needs no knowledge of `Cpu`'s layout.
- The manifest is split into lines from its bytes: a selftest manifest outgrew the longest string V8 can hold (512 MiB).
- `examples/emit_difftest.rs` takes `--from-frame <n>` to sample a title's later code. It maps no guest memory, so a folded PLT call (which reads its GOT slot) is not reported as covered.
- Guest memory uses the `crate::mem::Memory` shape: a top-level table of 4-byte entries per 2 MiB block, every one pointing at an empty block except the cases' window's, whose page entries are zero when unmapped (then every access hands back and `run` reports progress). Mapped pages are placed out of guest order so an access running off one page cannot find its guest neighbour behind it.
- `upto:<n>` (and `maybe-upto:<n>`) cases retire their first n instructions and hand back a terminator the interpreter faults on: register seeds put `x30` above 4 GiB, where the selftest's `ret` faults. Classifying those as `none` failed every one, since the emitted block rightly ran the instruction under test first.
- Each case carries the thread registers (`tpidr:`), the FPCR (`fpcr:`) and the clock origin (`clock:`) it started from. Without them, every block reading `TPIDRRO_EL0` differed on a register the harness had never seeded: three of 1,122 on Just Dance 2019.
- `NO_PC` poisons the pc before each case, so a block that should write it and does not is caught. The discard slot is skipped because a `CMP` fused into its branch is emitted without the discarded register write.
- A `none` mode case means the interpreter's watchpoint saw the access; an emitted block that went ahead anyway would blind the watchpoint. Memory is compared after every non-`exact` case, so a store with the right register effects but wrong bytes or address is caught.

## `crates/switch-core/examples/emit_selftest.rs`

- Complements `emit_difftest` (which covers only what a real title runs) with adversarial operands: 0 and -1 divisors, `INT_MIN` dividends, shift amounts at 32/64, all 16 NZCV settings per condition. It needs no title or keys, so it runs anywhere; CI does not run it.
- Encodings are swept from `cpu::emits` over all 2048 bits-31:21 prefixes rather than hand-written, since a wrong hand encoding silently tests a different instruction. Disassembly is used only for grouping and naming; the interpreter is the reference. The disassembler names no Advanced SIMD form, so those are bucketed by encoding with Rd, Rn and Rm masked. Random fills almost never land on a scalar FRINT, so those are swept on their own, a bucket per type and opcode, under every FPCR rounding mode (`fpcr:`).
- The sweep that added SIMD found two interpreter bugs, both confirmed on an arm64 host: ORR/BIC (vector, immediate) replaced the register instead of modifying it, and SIMD&FP register-offset loads read Rm 31 as SP instead of XZR.
- Random fills of the `MRS` space never land on one system register, so the generic timer's eight (`S3_3_C14_C0_<op2>`, CNTFRQ/CNTPCT/CNTVCT among them) are swept on their own, a form each, under clock seeds at the conversion's quotient and remainder edges.
- Buckets are keyed by the instruction's disassembly with registers and immediates replaced; mnemonic plus bit 31 conflated `ldr w`/`ldr x` and left 64-bit and sign-extending loads untested.
- Guest memory: a 17-page window at address 0 (so small seeds are addresses), pages scattered in module memory (prime count) so cross-page accesses must take the boundary path. The fill pattern differs at every load width and sign. Read and write watchpoints, a cached page and two write-protected pages with writable pages between are armed, so every hand-back reason is reachable.
- Faulting cases are kept: the expected result is "block retired nothing, state unchanged".
- Register seed sets pair `i64::MIN` with -1 (SDIV overflow, which traps in wasm) and ramp shift amounts around 32 and 64 (A64 takes them modulo operand width, wasm modulo its own). One set targets the last bytes of pages so accesses straddle into a mapped page. Another holds doubles with few significant bits and small exponents (`mixed_double` in `examples/common/emit.rs`, reproduced as `mixedDouble` in `emit_difftest.mjs`), which noise never produces and which put fused multiply-adds on exact ties. The exclusive monitor is armed for pairs too, and its snapshots (`excl:`) carry both doublewords.

## `crates/switch-core/examples/a32_emit_selftest.rs`

- Generates random data-processing, load/store, `LDM`/`STM` and branch encodings by field, emits each under several register sets and flag values, and records the interpreter's result; `node tools/emit_difftest.mjs --out=target/a32-emit-selftest` runs the modules under V8. It also covers VFP, Advanced SIMD, `LDRD`/`STRD` and `SBFX`/`UBFX`, seeding the vector registers and FPSCR. A case with a float operation carries `nansign`: the interpreter's compiled `a + b` and the engine pick different NaNs when both operands are one, so every word that reads as a NaN is compared as the canonical NaN. Memory cases hold one instruction, since a multi-instruction body may hand back partway.

## `crates/switch-core/examples/jit_coverage.rs`

- Emitter coverage is answered statically by `switch_core::cpu::emits`, plus `writes_exit` for the branches it writes as exits or terminators (not `translates`, which says yes to forms the emitter still refuses), weighted by a real frame's instruction mix, not by host timing.

## `crates/switch-core/examples/a32_jit_coverage.rs`

- The A32 counterpart, with `a32_translates` and `a32_emits`. It skips `--skip` steps, measures `--window` instructions one by one, and ranks the classes (bits 27:20 and 7:4) the emitter has no writer for. On Mario Kart 8 Deluxe (3B steps in, 100M measured, 32k distinct words) 0.60% decodes to the interpreter and 0.03% has no writer, a long tail under 0.01% per class (plain acquire loads, `CLZ`, `UDIV`, a load multiple naming its base, barriers, the reciprocal estimates, VFP v8 forms).

## `crates/switch-core/tests/jit_test.rs`

- The JIT tests are differential (registers, flags, vectors, pc, retired count, written memory) against the interpreter, on an `llvm-mc` + `ld.lld` corpus that also samples ops the translator deliberately hands back (system registers, scalar FP). A separate test checks that the corpus executes, since two runs that both fault immediately would also match.

## `crates/switch-core/tests/jit_emitted_test.rs`

- Runs the emitted path on the host with a fake `JitHost` whose entries are Rust functions doing what the block's first `retired` ops would.

## `crates/switch-core/tests/jit_a32_test.rs`

- Runs `llvm-mc` programs both ways and compares registers, flags, cycles, steps and memory at every step budget.
