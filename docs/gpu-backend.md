# The `wgpu` backend

`switch-gpu` is the `wgpu` backend behind `gpu::renderer::Renderer`; the software rasterizer is the reference it must agree with. Core GPU notes are in [gpu.md](gpu.md).

Section headings are paths under `crates/switch-gpu/src/`; a heading that starts with `crates/`, `tools/` or `web/` is from the repository root.

**It never blocks in a browser.** Reading a render target back means awaiting a promise, and a blocking wait there deadlocks. So a surface stays on the device across every draw targeting it and returns to guest memory only at `Renderer::flush`, which the engine calls before `present`. Opening the device is asynchronous too: the worker's loop calls `switch_gpu_open` as it starts, and the first slices draw on the rasterizer until it resolves. Any draw the backend cannot express falls back to `Software`. `Renderer::flush` polls with `PollType::Wait`, a real wait natively and a no-op on WebGPU, so a browser gets `Flush::Pending` and the present waits for a later slice (`Cpu::complete_pending_present`; why it must is under [renderer.rs](gpu.md#rendererrs)).

**Where a readback lands late, a frame is all one renderer's.** The first flush answering `Pending` sets `Gpu::deferred_readbacks`; only then does a frame in which anything fell back make the frames after it wholly the rasterizer's (`Gpu::software_frame`), since a mid-frame fallback would read stale memory that the late readback then overwrites. The latch is deliberate, because alternating costs a frame with the rasterizer's draws under a readback each time. It also lets go: each draw of a rasterizer frame goes through `Gpu::check` (pipeline state, surfaces, route, shader translation; no uploads), and after `clean_frames_needed` frames in a row in which every draw passed, the device gets the frames back. The first release takes one clean frame; each relatch after a release doubles the wait, since the check cannot see a fallback that an upload or the device itself causes. Tomodachi Life is why: one draw in its first 740 frames samples a per-pixel bindless handle, and a latch that never let go gave the rest of the session to the rasterizer. What buys the acceleration back is still `shader::wgsl`: almost every fallback that latches is an opcode with no WGSL form, not anything WebGPU withholds.

**Two kinds of work run on the rasterizer without counting as a fallback**, since they read no render target and nothing landing late can overwrite them: a draw the rasterizer only vertex-shades for its stores (`raster::only_shades_vertices`: points or lines whose vertex shader stores to global memory and samples nothing), and a colour clear of a target the device cannot hold that overlaps no held surface or readback in flight (`Gpu::clear_touches_nothing_held`). Nintendo Switch Sports does both every frame (the points draw under [raster/](gpu.md#raster), and clears of `R16_UNORM` targets), and each relatched the frames on its own, the wait doubling to thousands of frames.

**Each GPU address space has its own surfaces and caches.** Processes map different memory at the same GPU addresses, so held surfaces, readbacks and the texture and shader caches live in a `Space` per address space. Every renderer entry enters the `ExecCtx`'s space (`Gpu::enter_space`) and parks the rest; a flush writes back only its own space's surfaces, and a closed address space's device textures are destroyed (`Renderer::address_space_closed`). The texture cache's byte limit is shared, and reaching it clears every space.

**Dropping the backend destroys what it made.** wgpu's web backend frees nothing on drop and leaves it to the garbage collector, so `Gpu`'s `Drop` destroys every space's textures, the scratch resources and the device, when a session is freed or a lost device is replaced.

**A copy out of a held surface flushes first.** The copy engine and compute read guest memory, so `channel.rs` hands the surfaces back before `copy::LAUNCH_DMA` and `compute::SEND_SIGNALING_PCAS_B` ([gpu.md](gpu.md#channelrs)). A copy that is one plain run overlapping nothing held skips it (`Renderer::guest_memory_is_current`): Minecraft uploads constants this way, hundreds of small runs a frame, and each sent every surface back.

**2D blits run where their surfaces are.** `Renderer::blit` answers before `Engine2D::LAUNCHES_BLIT` runs: `Done` when the source is, or can be, held as the surface the registers name and the destination takes the same colour format (`blit.rs`, the engine's per-texel arithmetic in a shader, byte-identical with it in the parity tests); `GuestMemory` when neither surface overlaps anything held or on its way back, so no flush is needed; `Flush` otherwise. A blit whose surfaces overlap nothing held still goes to the device when it covers at least 256x256 texels (`UPLOAD_BLIT_TEXELS`): Minecraft's menus filter a 2560x720 image nothing draws to, which took 60% of the emulator thread on the CPU every frame. Guest writes are checked first, so a changed source goes through a flush instead of being read stale. Routing a resolve through guest memory was most of a frame in A Short Hike.

**A present brings back only what the display reads.** `submit_frame` reads back the scan-out surface, which stays held and clean (`send_back_kept`: a swap chain's buffers come round again, and each re-upload was 3 ms of a 1080p frame), and whatever the guest rebound, which does not; every other surface stays held and dirty across the present. Reading all of them back, destroying them and re-uploading them next frame was most of what remained. `Space::sync_all` requests the old full sync at the next present when something else depends on guest memory: a texture upload overlapping a dirty surface or a blit reading one. More than `MAX_HELD_BYTES` held does the same. A guest write to a held surface's pages, or a new surface aliasing a held one, sends back only the surfaces involved (`Space::aliased`): Mario Kart 8 Deluxe's title screen aliases a 320x180 surface inside a 1280x720 one every frame, and the full sync it used to ask for read back and re-uploaded about 27 MiB per frame. **A guest reading a render target's memory directly, with no copy, is not seen.** `--sync-every-present` on `screenshot` restores the full sync, to compare frames byte for byte.

**The display is drawn from the device.** In a browser the backend owns the canvas as a WebGPU surface (`Gpu::set_screen`, `screen.rs`). `Cpu::present_when_landed` first asks `Gpu::present_on_device`, which hands the backend a `ScanOut` (address, format, layout, crop, flips); when the backend holds that surface, `scan_out` draws the queued window of it onto the canvas, one texel to a pixel, with no readback and no pass through guest memory. The surface stays held and dirty like any other, so guest memory only catches up when something needs it. The pass shows the bytes as they are, so an sRGB-typed target on a non-sRGB display format is sampled and written through sRGB views of the same bytes. The old path still serves everything else: a second layer, a surface the backend does not hold (a cropped or multisampled one, or one a guest write made stale), `ROT_90`, a backend without a canvas, and frames the CPU rasterizer drew, which `show_pixels` uploads and draws on the same canvas. Native tools have no canvas and keep reading guest memory. A guest that reads its own swap chain's memory with the CPU is not seen.

**An attribute past its stride reads from a later buffer.** Maxwell takes any offset and WebGPU wants it inside the stride, so `within_stride` binds such an attribute's array whole strides later (appstore's offset 32 on stride 8).

**Depth, clears and multisampling all run on the device.** A depth surface is held like a colour one, as `depth16unorm` or `depth32float` (why, under [upload.rs](gpu.md#uploadrs)). Stencil is neither tested by either renderer nor held on the device: it stays in guest memory around the depth bytes, and stencil clears go there. Clears are a pass's load operation where they cover the whole surface and a scissored fullscreen draw where they do not.

**Multisampling has two routes, and the default is the exact one.** Guest memory holds the expanded image, a `samples_x` by `samples_y` tile of texels per pixel ([surface.rs](gpu.md#surfacers)), and the default route renders exactly that: one fragment per texel, testing coverage at texel centres where Maxwell's samples are, with the sample mask and alpha-to-coverage in the fragment shader ([shader/wgsl/](gpu.md#shaderwgsl)). `AntiAliasEnable = 0` renders through a per-pixel companion whose result fills every texel of the tile. Samples programmed away from their texel centres (`SampleGrid::samples_at_texel_centres`) draw once per sample: each pass moves the viewport by the sample's offset inside its texel (`SampleGrid::texel_shift`), and its pipeline's `pass_sample` constant keeps only that sample's texels, so coverage and depth are the rasterizer's; varyings interpolate at the moved texel centre. Every sample at the pixel centre takes the per-pixel route instead. One case still falls back deliberately: per-pixel coverage with a partial sample mask or alpha-to-coverage. `--device-msaa` lets the device multisample instead. It is off because WebGPU's sample positions are a rotated grid unlike Maxwell's, and core WebGPU guarantees only four samples, so in a browser `2x1`, `4x2` and `4x4` take the expanded route regardless. Natively, with `TEXTURE_ADAPTER_SPECIFIC_FORMAT_FEATURES`, the device takes any count the adapter offers for every attachment format (`samples_supported`).

**Two renderers disagree by a 255th where a channel lands on a half**: `ColorFormat::encode` rounds `127.5` up and a device's unorm conversion rounds it down, so a test wanting byte-identity picks values off the eight-bit half-way points.

**Checking the backend** means running `screenshot` with and without `--software` over the same frame and `cmp`ing the PPMs; a byte-identical pair is the only evidence it renders what the rasterizer does, and `--only <i>` (or `<a>..<b>`) narrows a difference to one draw. `gpu::testing::Harness` is the faster half: a drawable `Engine3D` that both renderers are driven over, so a route can be checked without booting a title. hbmenu is not a shader-core test: its command list is `dkCmdBufCopyBufferToImage` plus a fence.

## `convert.rs`

- Formats behind optional WebGPU features must be refused up front: `createTexture` throws on a missing feature and wgpu's web backend unwraps it, which on wasm is an `unreachable` trap that kills the core (Just Dance 2019's first BC1 texture).
- Normalized 16-bit formats (`TEXTURE_FORMAT_16BIT_NORM`) are native-only; no browser offers them. Sampled textures in those formats are widened to the 32-bit float sibling, which is exact (`f32` has 24 significand bits) and needs `float32-filterable`. Render targets in those formats stay refused: float targets neither clamp nor blend like normalized ones, and readback copies texels straight into a 16-bit guest surface.
- Attachment support is checked through the format's allowed usages, not required features: `rg11b10ufloat` samples without a feature but rendering needs `RG11B10UFLOAT_RENDERABLE`.

## `stats.rs`

- All device rejections are kept (distinct messages capped at 16, plus a total count), not just the first: `device_error` takes only the oldest, and is read only before pipeline creation and when a readback fails to map, so later errors went unread.
- Upload accounting is in bytes, not time (the same on host and V8); it showed textures dominate upload bytes, which is why textures are cached. Cached textures are not counted.
- `flush` splits into ask/wait/land. In a browser `flush_wait` is ~0 because the wait moved to the slice boundary (`Flush::Pending`).

## `lib.rs` and `device.rs`

- `wgpu` lives in its own crate to keep `switch-core` dependency-free; the `Renderer` trait is the only shared surface.
- Device features requested (masked to the adapter's): the compressed texture families; `TEXTURE_FORMAT_16BIT_NORM` and `FLOAT32_FILTERABLE` (see `convert.rs`); `SUBGROUP` for warp shuffles (native only; browsers use `QUAD_SWAP`, under [shader/wgsl/](gpu.md#shaderwgsl)); `TEXTURE_ADAPTER_SPECIFIC_FORMAT_FEATURES` for 2/8 sample counts (without it the device allows only 1 and 4, and the adapter's answer lies, silently producing empty draws); `RG11B10UFLOAT_RENDERABLE` (Tomodachi Life's HDR target); `FLOAT32_BLENDABLE`. The storage buffer limit is raised to the adapter's because each `ldg` buffer is a storage binding beside the stage's one constant buffer. `--web-limits` hides the native-only features so a native run takes the browser's routes.
- The `wgpu::Instance` and adapter must be held for the device's lifetime: a browser loses the device ("A valid external Instance reference no longer exists") once they are collected.
- Per-draw buffers and textures, readback staging buffers and flushed surfaces are `destroy()`ed rather than dropped: a browser frees dropped resources only on GC, which led to `VK_ERROR_OUT_OF_DEVICE_MEMORY` (Just Dance 2019) and OOM in Persona 5 Royal. `destroy()` is safe once the submission is made.
- Caches: shader modules keyed by WGSL hash (compiling costs far more than translating), and the module of each translation and layout pair (`built_modules`), so a repeated draw neither writes nor hashes its WGSL; the device's features and limits, read once, since a browser rebuilds them from JavaScript on every query (27% of Persona 5 Royal's main worker at its load screen); pipelines keyed by `PipelineKey`; samplers (`createSampler` is slow in browsers); bind group layouts; translated shaders by address and stage, evicted by page writes and validated against `brx` jump tables read from constant buffers; deswizzled textures, evicted on watched page writes, with whole-cache eviction at 256 MiB (`TEXTURE_CACHE_BYTES`). Texture source pages are walked only as far as the mapping (Asphalt 9 textures claim 16 MiB in a 6 MiB mapping).
- A stage's bind group is cached by its layout entries, its constant and global bytes, and the texture, sampler and view dimension objects it binds (`Gpu::bind_groups`, with the buffers it owns). A stage binding a scratch texture (a copy over a held surface, or a shadow map), a texture the cache does not keep, a held global or a global the shader writes is built per draw. Texture eviction destroys the texture, so its entries are never hit again; the cache starts over after a draw once it holds 2048. Mario Kart 8 Deluxe's title built 251,460 groups from 4,745 distinct ones; with the cache its bind group time fell from 21.7 to 3.3 ms a frame in the browser and the title went from 4 to 8 fps to about 30.
- Device errors are captured by the uncaptured-error handler and read later (error scopes would require waiting). Device loss is otherwise silent (submissions accepted, readbacks never map); on loss, `give_up` hands every later frame to the rasterizer and the reason goes into the report rather than an error, since flush also runs inside GPU submissions (an error faulted Persona 5 Royal). `lost()` then answers true and the worker opens a new device ([renderer.rs](gpu.md#rendererrs)).
- `--defer-readbacks` reproduces the browser's late readbacks natively. `--interleave` interleaves fallback draws into device frames anyway, trading a few wrong pixels for much faster frames. A proper browser fix would yield the pushbuffer at the fallback so the next slice resumes with the readback landed.
- Flush returns early when nothing is held, evicted or pending: flush runs before every fallback draw, and empty polls showed up as seconds in a no-draw browser trace.
- A plain 2D image taller than the device allows (no mipmaps, uncompressed rows) is folded into array layers of overlapping tiles (`wgsl::Fold`): Nintendo Switch Sports draws its text from a 1024x32768 `R8` glyph atlas, and every text draw fell back. Tiles share a row, so bilinear filtering and gathers read both rows from one tile and match the unfolded image exactly; rows past the end repeat the last, which is clamping. A repeating image (the atlas repeats) gets one more tile holding its last row and then its first, the only pair no other tile holds; the shader wraps the row before choosing a tile, so the sampler clamps v on every folded image. A mirrored v wrap is refused. Anything else past the device's limits is refused before `create_texture`: an invalid texture poisons every bind group made with it, and the draws after it are rejected.
- `tlds` fetches by integer coordinates in every encoding of Eden's `texture_load_swizzled.cpp` but 6 (multisample, which no sampled image here has), and refuses the register pairs Eden refuses as unaligned. The texture model holds level 0 only and the device is given one level, so a nonzero level register faults in `interp` and a level register other than `RZ` leaves the shader to the interpreter; a 1D fetch reads row 0 of a 2D image, since a 1D TIC is refused. An offset is added to the coordinates with wrapping, so a negative one past 0 is outside the image and reads zero on both. A folded image's fetch is checked by WGSL text and naga only.
- `tld4` and `tld4s` read `.AOFFI` as Eden does, signed six-bit fields at bits 0 and 8 (`tex`'s are four-bit nibbles at 0 and 4). A register offset moves the coordinates by whole texels before the gather in `interp` and in the WGSL (`texStep`, `1 / size` with a folded image's own height), because `textureGather` takes only a constant offset. `.PTP` gathers four times, each moved by its own offset, keeping that gather's texel. A cube gather picks its face as `sample_cube_with` does and reads a footprint over a face edge from the neighbouring face (`cube_neighbour`), as the device's seamless `textureGather` does; a footprint over a corner has no single neighbour and may differ. Not implemented: 1D, array-1D and 3D gathers (WebGPU has no `textureGather` form for them, and the texture model refuses 1D images), and an offset on a cube (Eden refuses it too).
- An integer image (`RGBA32Uint`) is read at the nearest texel on both renderers and bound with a non-filtering sampler of nearest filters, so `textureGather` of it is valid; its gathers and constant-offset samples carry the words as `bitcast<vec4<f32>>`. A swizzle other than the identity still refuses the draw.
- A held `ZF32` sampled smaller than it is held (rows laid out the same) copies the whole surface into the buffer and the sampled corner out of it, since depth copies take whole subresources. A held surface stands in for a slice of a deep-block volume only where the slice fits one GOB, where volume and surface addressing coincide; slice `z` is looked for where the volume puts it, not `z` layer strides along.
- Held surfaces sampled as textures must be copied from the device, not read stale from guest memory (Tomodachi Life's HDR reduction chain and cube faces). Float held depth (`ZF32`, and `ZF32_X24S8` whose stencil the device never holds) is copied via a buffer into `r32float` (Nintendo Switch Sports, Persona 5 Royal). Held `Z24S8` sampled as `S8D24` is converted into the `rg32float` image by `PACKED_DEPTH_WGSL` (`fs_held`: depth from the held surface, stencil from the uploaded words), which quantizes to 24 bits and decodes in integer arithmetic so the value is bit-identical to the rasterizer's (A Short Hike). Padded surfaces sampled at their drawn size use the corner path when row layouts match (`same_rows`). Draws may sample their own target, so held layers are copied into a fresh texture; only a one-layer colour surface of the sampled size and format, unwidened, that the draw does not render to is bound directly (`directly_sampled`).
- Attachments must match in size: the pass covers the colour/depth intersection; a larger depth surface is cropped, and a larger colour target draws into a scratch texture copied back (WebGPU copies part of a colour texture but only whole depth textures).
- WebGPU details: no border address mode (wgpu web panics; the rasterizer also treats border as edge); strip pipelines must name the index format and non-strip pipelines must not, or the whole command buffer is rejected; Metal drops vertices whose stride overruns the buffer. The missing BGRA vertex format, per-texture swizzle and the y mirror are handled in the shader ([shader/wgsl/](gpu.md#shaderwgsl)).
- Maxwell has 32 vertex arrays and WebGPU guarantees 8 buffers, which is all Chrome offers. Mesa gives each attribute its own array, so Taisei draws from 11; binding them all made the device reject the pipeline and handed the session to the rasterizer. Past the device's count, `fit_vertex_buffers` interleaves the per-vertex arrays into one buffer (they share the draw's first vertex and count) and puts every zero-stride element (instanced arrays, the defaults) into a second. Draws within the count bind as before.
- `Renderer::report` nests timings to avoid duplicate "modules" keys (`JSON.parse` keeps only the last). Timings are written with one decimal place (`json::Decimals`) to keep the report short.

## `readback.rs`

- Readback is copy to staging, map, read: three steps that cannot happen in one call on the web. The map callback runs from the event loop, so state is an atomic polled by the next slice. Each ask for a frame's surfaces is a generation, at most two in flight, landed in order; a present waits on its generation.
- Memory that shaders write with stores or atomics is held on the device per descriptor address (`Space::globals`, sized by the size word NVN keeps after the descriptor's address, else to the end of its mapping, up to 8 MiB; the translator counts the size word as read so the bank upload reaches it) and asked back at every flush and present. Only the words that differ from the upload land, so a guest write elsewhere in the buffer in between survives. Written buffers are sub-allocations of one pool and may overlap; a later draw that only reads over one refuses until the flush, and so does the rasterizer's draw, which flushes first. A guest read of the memory before the next present sees the old words, as it does for held surfaces. A written buffer stays alive until its readback lands, so a draw in between can still read it.
- Compute launches run on the device (`compute.rs`) when the translator takes the program; one it refuses (barriers, shared memory, warp instructions, textures, packed `SR_TID`/`SR_NTID`) goes to the software dispatch after a flush, as every launch used to. The device route skips that flush: Persona 5 Royal launches about 40 a frame, each of which flushed every held surface. What a launch writes is a held global. A draw whose vertex array overlaps one copies the written bytes over the stale guest bytes on the device (`Patch`, before the pass), from buffers still on their way back first so the newest wins; one whose indices or constants overlap, or whose vertex bytes were rearranged on the CPU, refuses and flushes. `touches_nothing_held` counts held globals, so a copy or blit over them flushes too. A buffer a launch only reads is uploaded once and kept by address and length (`Space::inputs`, `compute_input`) until the guest writes its pages or the address maps to other pages.
- A held surface sampled as a texture that it does not cover exactly is copied into a texture of the sampled shape (`texture_over_held`). When the held layers cover every layer, guest memory is not read at all, and the copy is kept (`Space::held_copies`) until a source is written again: every write bumps `Held::writes`, and a copy is reused only while each source is the same texture at the same count. Persona 5 Royal samples two 1024x1024 shadow maps and its depth buffer in about 310 draws a frame; uploading and copying them per draw was 389 s of an 866 s native run to its menu, which now takes 455 s. A padded held colour surface sampled out of its top-left corner, clamped to the edge on both axes and only ever sampled (no gather, fetch or size query, which the translator records as `read_otherwise`), is bound in place instead (`crop_of_held`, `wgsl::Crop`): the module scales the coordinates to the surface and clamps them to the image's outermost texel centres, which filters exactly as clamping the copy would, nearest or linear. A repeating or mirrored wrap would filter in the padding at the edge, so those keep the copy.
- Depth row bytes are the device format's: `Z24S8` is 4 bytes in memory and 4 bytes of `f32` on the device; `ZF32_X24S8` is 8 and 4.
- A companion surface is resolved back into the held surface before the readback, so guest memory only sees the expanded form; its grid is stored because the register file has moved on by flush time.

## `builtin.rs`

- Depth uploads and shadow maps go through a fullscreen draw writing `frag_depth` from an `r32float` texture (`LOAD_DEPTH_WGSL`, one layer at a time), because a copy cannot write `depth32float`. `depth16unorm` could be copied but takes the same draw path so the two formats cannot diverge.
- The resample grid is a storage buffer, not a uniform: its tables are indexed by a runtime value, and a uniform array pads every element to 16 bytes.

## `tests.rs`

- `shader::wgsl` dispatch keeps an unreachable trailing `return false;` because naga requires it (Tint warns); a test fails once naga stops requiring it.
