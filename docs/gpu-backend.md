# The `wgpu` backend

`switch-gpu` is the `wgpu` backend behind `gpu::renderer::Renderer`; the software rasterizer is the reference it must agree with. Core GPU notes are in [gpu.md](gpu.md).

Section headings are paths under `crates/switch-gpu/src/`; a heading that starts with `crates/`, `tools/` or `web/` is from the repository root.

**It never blocks in a browser.** Reading a render target back means awaiting a promise, and a blocking wait there deadlocks. So a surface stays on the device across every draw targeting it and returns to guest memory only at `Renderer::flush`, which the engine calls before `present`. Opening the device is asynchronous too: the worker's loop calls `switch_gpu_open` as it starts, and the first slices draw on the rasterizer until it resolves. Any draw the backend cannot express falls back to `Software`. `Renderer::flush` polls with `PollType::Wait`, a real wait natively and a no-op on WebGPU, so a browser gets `Flush::Pending` and the present waits for a later slice (`Cpu::complete_pending_present`; why it must is under [renderer.rs](gpu.md#rendererrs)).

**Where a readback lands late, a frame is all one renderer's.** The first flush answering `Pending` sets `Gpu::deferred_readbacks`; only then does a frame in which anything fell back make the frames after it wholly the rasterizer's (`Gpu::software_frame`), since a mid-frame fallback would read stale memory that the late readback then overwrites. The latch is deliberate, because alternating costs a frame with the rasterizer's draws under a readback each time. It also lets go: each draw of a rasterizer frame goes through `Gpu::check` (pipeline state, surfaces, route, shader translation; no uploads), and after `clean_frames_needed` frames in a row in which every draw passed, the device gets the frames back. The first release takes one clean frame; each relatch after a release doubles the wait, since the check cannot see a fallback that an upload or the device itself causes. Tomodachi Life is why: one draw in its first 740 frames samples a per-pixel bindless handle, and a latch that never let go gave the rest of the session to the rasterizer. What buys the acceleration back is still `shader::wgsl`: almost every fallback that latches is an opcode with no WGSL form, not anything WebGPU withholds.

**Two kinds of work run on the rasterizer without counting as a fallback**, since they read no render target and nothing landing late can overwrite them: a draw the rasterizer only vertex-shades for its stores (`raster::only_shades_vertices`: points or lines whose vertex shader stores to global memory and samples nothing), and a colour clear of a target the device cannot hold that overlaps no held surface or readback in flight (`Gpu::clear_touches_nothing_held`). Nintendo Switch Sports does both every frame (the points draw under [raster/](gpu.md#raster), and clears of `R16_UNORM` targets), and each relatched the frames on its own, the wait doubling to thousands of frames.

**Each GPU address space has its own surfaces and caches.** Processes map different memory at the same GPU addresses, so held surfaces, readbacks and the texture and shader caches live in a `Space` per address space. Every renderer entry enters the `ExecCtx`'s space (`Gpu::enter_space`) and parks the rest; a flush writes back only its own space's surfaces, and a closed address space's device textures are destroyed (`Renderer::address_space_closed`). The texture cache's byte limit is shared, and reaching it clears every space.

**Dropping the backend destroys what it made.** wgpu's web backend frees nothing on drop and leaves it to the garbage collector, so `Gpu`'s `Drop` destroys every space's textures, the scratch resources and the device, when a session is freed or a lost device is replaced.

**A copy out of a held surface flushes first.** The copy engine and compute read guest memory, so `channel.rs` hands the surfaces back before `copy::LAUNCH_DMA` and `compute::SEND_SIGNALING_PCAS_B` ([gpu.md](gpu.md#channelrs)). A copy whose source and destination overlap nothing held skips it (`Renderer::guest_memory_is_current`), each bounded by `EngineCopy::touched_ranges` as one span: a plain run, pitch rows (a negative pitch runs downwards), the block rows a block-linear rectangle crosses, and no source for a fill from the remap constants. Minecraft uploads constants as plain runs and textures as multi-line pitch-to-block copies, hundreds a frame; when only plain runs skipped, the uploads sent every surface back, its 1280x720 depth surface was read back and repacked once a frame, and in a browser each such flush also parked the channel until the readback landed (`Flush` 42.6 ms a frame, 2 to 5 fps on the title screen). A launch that copies nothing still flushes, since its semaphore may tell the guest rendered memory is ready.

**2D blits run where their surfaces are.** `Renderer::blit` answers before `Engine2D::LAUNCHES_BLIT` runs: `Done` when the source is, or can be, held as the surface the registers name and the destination takes the same colour format, or an 8-bit one the shader rounds itself (`blit.rs`, the engine's per-texel arithmetic in a shader, byte-identical with it in the parity tests); `GuestMemory` when neither surface overlaps anything held or on its way back, so no flush is needed; `Flush` otherwise, which sends back only what overlaps the two surfaces (`Renderer::sync_ranges`): a held surface the blit reads is read back and stays held, one it overwrites is let go, and the rest stay on the device. Echoes of Wisdom's refused blits each sent every held surface back before that, about 20 MB a frame. Its copy of a held `S8D24` depth surface, word for word, into a `B8G8R8A8` one runs on the device too (`PACKED_DEPTH_WGSL`'s `fs_blit`): each word is rebuilt from the stencil byte in guest memory, which the device never holds, and the held depth in unorm, as a readback would leave them. Its `Rg11b10Ufloat` frame converts into the sRGB one on the device: an sRGB target is rounded in sRGB and written as the linear value of that byte, since Metal's own encode of a filtered colour was a step off in a fifth of the texels. A converted side whose guest format has no alpha must have none on the device either, where an `X` format keeps whatever alpha was drawn. A blit whose surfaces overlap nothing held still goes to the device when it covers at least 256x256 texels (`UPLOAD_BLIT_TEXELS`): Minecraft's menus filter a 2560x720 image nothing draws to, which took 60% of the emulator thread on the CPU every frame. Guest writes are checked first, so a changed source goes through a flush instead of being read stale. Routing a resolve through guest memory was most of a frame in A Short Hike.

**A present brings back only what the display reads.** `submit_frame` reads back the scan-out surface, which stays held and clean (`send_back_kept`: a swap chain's buffers come round again, and each re-upload was 3 ms of a 1080p frame). A surface the guest rebinds goes back when it is rebound, and a frame shown on the device (`scan_out`, which skips `submit_frame`) still collects the readbacks that have landed: neither happened on that route, and Breath of the Wild, rebinding its G-buffer memory every frame, kept every replaced texture and then every readback until the GPU ran out of memory and took other applications' surfaces with it; every other surface stays held and dirty across the present. Reading all of them back, destroying them and re-uploading them next frame was most of what remained. `Space::sync_all` requests the old full sync at the next present when something else depends on guest memory: a texture upload overlapping a dirty surface or a blit reading one. More than `MAX_HELD_BYTES` held does the same. A guest write to a held surface's pages, or a new surface aliasing a held one, sends back only the surfaces involved (`Space::aliased`): Mario Kart 8 Deluxe's title screen aliases a 320x180 surface inside a 1280x720 one every frame, and the full sync it used to ask for read back and re-uploaded about 27 MiB per frame. Pages wholly inside the surface that the guest wrote are newer than the device's texels there (`Held::overwritten`): a texture lying within them is read from guest memory instead of the held surface, and the readback puts those pages back as the guest left them, until the device draws into the surface again. Just Dance 2022 puts a `BC3` image where a 1280x720 target was; sampling the stale target fell back, and its readback wrote the old pixels over the image. A page the surface shares with other data still takes the device's bytes. **A guest reading a render target's memory directly, with no copy, is not seen.** `--sync-every-present` on `screenshot` restores the full sync, to compare frames byte for byte.

**The display is drawn from the device.** In a browser the backend owns the canvas as a WebGPU surface (`Gpu::set_screen`, `screen.rs`). `Cpu::present_when_landed` first asks `Gpu::present_on_device`, which hands the backend a `ScanOut` (address, format, layout, crop, flips); when the backend holds that surface, `scan_out` draws the queued window of it onto the canvas, one texel to a pixel, with no readback and no pass through guest memory. The surface stays held and dirty like any other, so guest memory only catches up when something needs it. The pass shows the bytes as they are, so an sRGB-typed target on a non-sRGB display format is sampled and written through sRGB views of the same bytes. The old path still serves everything else: a second layer, a surface the backend does not hold (a cropped or multisampled one, or one a guest write made stale), `ROT_90`, a backend without a canvas, and frames the CPU rasterizer drew, which `show_pixels` uploads and draws on the same canvas. Native tools have no canvas and keep reading guest memory. A guest that reads its own swap chain's memory with the CPU is not seen.

**An attribute past its stride reads from a later buffer.** Maxwell takes any offset and WebGPU wants it inside the stride, so `within_stride` binds such an attribute's array whole strides later (appstore's offset 32 on stride 8). One that runs into the next element reads it there too, so its array is copied out at a stride that holds it, each element the bytes Maxwell reads at the old stride (Tears of the Kingdom's 8-byte `R16G16B16A16_FLOAT` on a 6-byte stride, whose alpha is the next vertex's red). An attribute off the offset alignment WebGPU asks of its format (`min(4, size)`; Tears of the Kingdom's 4-byte attribute at offset 10) is copied out the same way: the copy lays the part's attributes one after another, each on its alignment.

**Depth, clears and multisampling all run on the device.** A depth surface is held like a colour one, as `depth16unorm` or `depth32float` (why, under [upload.rs](gpu.md#uploadrs)). Stencil is neither tested by either renderer nor held on the device: it stays in guest memory around the depth bytes, and stencil clears go there. Clears are a pass's load operation where they cover the whole surface and a scissored fullscreen draw where they do not.

**Multisampling has two routes, and the default is the exact one.** Guest memory holds the expanded image, a `samples_x` by `samples_y` tile of texels per pixel ([surface.rs](gpu.md#surfacers)), and the default route renders exactly that: one fragment per texel, testing coverage at texel centres where Maxwell's samples are, with the sample mask and alpha-to-coverage in the fragment shader ([shader/wgsl/](gpu.md#shaderwgsl)). `AntiAliasEnable = 0` renders through a per-pixel companion whose result fills every texel of the tile. Samples programmed away from their texel centres (`SampleGrid::samples_at_texel_centres`) draw once per sample: each pass moves the viewport by the sample's offset inside its texel (`SampleGrid::texel_shift`), and its pipeline's `pass_sample` constant keeps only that sample's texels, so coverage and depth are the rasterizer's; varyings interpolate at the moved texel centre. Every sample at the pixel centre takes the per-pixel route instead. One case still falls back deliberately: per-pixel coverage with a partial sample mask or alpha-to-coverage. `--device-msaa` lets the device multisample instead. It is off because WebGPU's sample positions are a rotated grid unlike Maxwell's, and core WebGPU guarantees only four samples, so in a browser `2x1`, `4x2` and `4x4` take the expanded route regardless. Natively, with `TEXTURE_ADAPTER_SPECIFIC_FORMAT_FEATURES`, the device takes any count the adapter offers for every attachment format (`samples_supported`).

**Two renderers disagree by a 255th where a channel lands on a half**: `ColorFormat::encode` rounds `127.5` up and a device's unorm conversion rounds it down, so a test wanting byte-identity picks values off the eight-bit half-way points.

**Checking the backend** means running `screenshot` with and without `--software` over the same frame and `cmp`ing the PPMs; a byte-identical pair is the only evidence it renders what the rasterizer does, and `--only <i>` (or `<a>..<b>`) narrows a difference to one draw. `gpu::testing::Harness` is the faster half: a drawable `Engine3D` that both renderers are driven over, so a route can be checked without booting a title. hbmenu is not a shader-core test: its command list is `dkCmdBufCopyBufferToImage` plus a fence.

## `convert.rs`

- Formats behind optional WebGPU features must be refused up front: `createTexture` throws on a missing feature and wgpu's web backend unwraps it, which on wasm is an `unreachable` trap that kills the core (Just Dance 2019's first BC1 texture).
- Normalized 16-bit formats (`TEXTURE_FORMAT_16BIT_NORM`) are native-only; no browser offers them. Sampled textures in those formats are widened to the 32-bit float sibling, which is exact (`f32` has 24 significand bits) and needs `float32-filterable`. An unorm render target in those formats is held as the same float sibling (`held_attachment_format`): the fragment shader clamps and rounds what it writes to 16 bits (`Layout::unorm16_targets`), clears are rounded the same way, an upload widens the guest's texels and a readback narrows them back. Sampling it later reads exactly the 16-bit values the rasterizer would. A blend into one falls back unless it cannot leave `[0, 1]` (`Blend::stays_in_unit_range`: a mix of two terms whose factors sum to one, min or max, or one term alone), since a float target does not clamp as it blends; Breath of the Wild's lighting probes mix by a constant alpha every frame of its shrine, and each fall-back handed the browser's frame to the rasterizer, and so do multisampled draws with coverage per sample, storage images and 2D blits into one. Breath of the Wild draws into `R16_UNORM` targets unblended.
- Attachment support is checked through the format's allowed usages, not required features: `rg11b10ufloat` samples without a feature but rendering needs `RG11B10UFLOAT_RENDERABLE`.

## `stats.rs`

- All device rejections are kept (distinct messages capped at 16, plus a total count), not just the first: `device_error` takes only the oldest, and is read only before pipeline creation and when a readback fails to map, so later errors went unread.
- Upload accounting is in bytes, not time (the same on host and V8); it showed textures dominate upload bytes, which is why textures are cached. Cached textures are not counted.
- `flush` splits into ask/wait/land. In a browser `flush_wait` is ~0 because the wait moved to the slice boundary (`Flush::Pending`).

## `lib.rs` and `device.rs`

- `wgpu` lives in its own crate to keep `switch-core` dependency-free; the `Renderer` trait is the only shared surface.
- Device features requested (masked to the adapter's): the compressed texture families; `TEXTURE_FORMAT_16BIT_NORM` and `FLOAT32_FILTERABLE` (see `convert.rs`); `SUBGROUP` for warp shuffles (native only; browsers use `QUAD_SWAP`, under [shader/wgsl/](gpu.md#shaderwgsl)); `TEXTURE_ADAPTER_SPECIFIC_FORMAT_FEATURES` for 2/8 sample counts (without it the device allows only 1 and 4, and the adapter's answer lies, silently producing empty draws); `RG11B10UFLOAT_RENDERABLE` (Tomodachi Life's HDR target); `FLOAT32_BLENDABLE`. The storage buffer limit is raised to the adapter's because each `ldg` buffer is a storage binding beside the stage's one constant buffer. `--web-limits` hides the native-only features so a native run takes the browser's routes.
- The `wgpu::Instance` and adapter must be held for the device's lifetime: a browser loses the device ("A valid external Instance reference no longer exists") once they are collected.
- Per-draw buffers and textures, readback staging buffers and flushed surfaces are `destroy()`ed rather than dropped: a browser frees dropped resources only on GC, which led to `VK_ERROR_OUT_OF_DEVICE_MEMORY` (Just Dance 2019) and OOM in Persona 5 Royal. `destroy()` is safe once the submission is made, so past `MAX_SCRATCH_BYTES` of them the open batch is submitted early rather than holding them to the next present: Breath of the Wild once reached 4.6 GiB of stale held copies in one pass.
- Consecutive draws to the same colour and depth textures share one render pass (`Gpu::pass`, kept open with `forget_lifetime`); a draw that needs a copy first (compute patches, a colour scratch, a vertex stage's copy of a written global) opens its own, and so does one binding a held global with the other access than the pass already binds it (`OpenPass::globals`), since a pass is one usage scope and a writable buffer cannot be bound read-only beside itself, and `submit_batch`, `submit_with_batch` and compute launches end it before using the encoder. About 90% of Persona 5 Royal's draws join the pass before them, which takes its menu from about 1,800 passes a frame to 180.
- Clears, depth crop copies, copies of held layers and packed depth conversions are recorded into the draws' batch (`Gpu::take_batch`) rather than submitted on their own, since commands in one encoder run in order: a draw recorded before a copy still reads what it overwrites. A queue write lands before the whole batch, which is safe only because every `write_texture` and `write_buffer` here goes to a resource made for it, to the constant arena at offsets no recorded draw reads, or to the screen's frame texture, whose pass is submitted at once. What these used to destroy at once goes to `Gpu::scratch`. Pokémon Legends: Z-A switches depth crops about 26 times a frame and made about 170 submits a frame; it makes about 30 now. A recorded copy that the device rejects invalidates the whole batch, not just itself.
- Caches: shader modules keyed by WGSL hash (compiling costs far more than translating), and the module of each translation and layout pair (`built_modules`), so a repeated draw neither writes nor hashes its WGSL; vertex and index buffers by their bytes (`shared_buffer`; a draw whose vertices a compute launch patched keeps its own), since most draws repeat a mesh; the device's features and limits, read once, since a browser rebuilds them from JavaScript on every query (27% of Persona 5 Royal's main worker at its load screen); pipelines keyed by `PipelineKey`; samplers (`createSampler` is slow in browsers); bind group layouts; translated shaders by address and stage, evicted by page writes and validated against `brx` jump tables read from constant buffers; deswizzled textures, evicted on watched page writes, with whole-cache eviction at 256 MiB (`TEXTURE_CACHE_BYTES`). Texture source pages are walked only as far as the mapping (Asphalt 9 textures claim 16 MiB in a 6 MiB mapping).
- The device asks for the adapter's sampled-texture limit (48 in Chrome) but keeps 16 samplers, all Chrome gives. A stage sampling more textures than that binds each distinct sampler once (`share_samplers`, `TextureBinding::sampler`); under the limit nothing is shared, so a module does not change with the samplers its draws happen to use. Echoes of Wisdom samples 19 textures in one fragment shader.
- A stage's bind group is cached by its layout entries, its global bytes, the size its constants are bound at, and the texture, sampler and view dimension objects it binds (`Gpu::bind_groups`, with the buffers it owns). A stage binding a scratch texture (a copy over a held surface, or a shadow map), a texture the cache does not keep, a held global or a global the shader writes is built per draw. Texture eviction destroys the texture, so its entries are never hit again; the cache starts over after a draw once it holds 2048. Mario Kart 8 Deluxe's title built 251,460 groups from 4,745 distinct ones; with the cache its bind group time fell from 21.7 to 3.3 ms a frame in the browser and the title went from 4 to 8 fps to about 30.
- Constants are not part of a bind group: every draw's packed banks go into one arena buffer (`Gpu::stage_constants`), bound at a dynamic offset and written with one `writeBuffer` before each submit, so a changed constant changes no group. The binding's size is rounded up to a power of two so groups repeat; `cbRead` bounds each bank by the table at the front, never by the binding. A flush writes only the bytes placed since the last one, since draws recorded and not yet submitted still read the older ones. The arena starts over at any submit that no draw in progress has placed constants before (`constants_unrecorded`), and submits early of its own only when full; a draw's second stage that would wrap it takes a buffer of its own instead, since starting over would let later draws overwrite the first stage's. Constants a compute launch patched keep a buffer of their own, bound at offset 0.
- A draw joining the open pass sets only the bind groups, buffers, pipeline, viewport, scissor and blend constant that differ from what the pass last had (`PassState`), since each call crosses into JavaScript in a browser. Texture views are kept by texture and dimension (`Gpu::view`) for the same reason. Each draw is held back in the pass (`OpenPass::pending`), and the next one widens its instance range instead of drawing on its own when it is the following instance of it and sets nothing but its instanced arrays; `end_pass`, which every route closing a pass goes through, records it (`Gpu::emit_pending`). An instanced array uploads one element a draw, read at stride zero, so a widened call keeps each instance's element and records through a pipeline reading those arrays at the element's stride (`Recipe::with_strides`), from a buffer that puts instance `k`'s element `k` strides in. Mario Kart 8 Deluxe's title draws 65% of its draws as a later instance, almost all reading an instanced array. Maxwell draws each instance as its own draw, so this needs repeated constants to keep their arena offset: `stage_constants` hands back each stage's last placement when the bytes are the same.
- A texture is put in the cache by `prepare` (`keep_textures`), before the draw binds it, and its pages are watched once `ctx` is mutable. Caching it after the draw made its first draw upload it as scratch and the next upload it again.
- Device errors are captured by the uncaptured-error handler and read later (error scopes would require waiting). Device loss is otherwise silent (submissions accepted, readbacks never map); on loss, `give_up` hands every later frame to the rasterizer and the reason goes into the report rather than an error, since flush also runs inside GPU submissions (an error faulted Persona 5 Royal). `lost()` then answers true and the worker opens a new device ([renderer.rs](gpu.md#rendererrs)).
- `--defer-readbacks` reproduces the browser's late readbacks natively. `--interleave` interleaves fallback draws into device frames anyway, trading a few wrong pixels for much faster frames. A proper browser fix would yield the pushbuffer at the fallback so the next slice resumes with the readback landed.
- Flush returns early when nothing is held or pending: flush runs before every fallback draw, and empty polls showed up as seconds in a no-draw browser trace.
- A texture past `MAX_UPLOAD` uploads its largest mip level under the cap (`TextureUpload::shrink` levels down) in place of being refused; Tears of the Kingdom samples 121-layer arrays of 1024x1024 ASTC, 484 MiB once decoded to RGBA8. Sampling is unchanged since coordinates are normalized; `txq`, `tlds` and constant texel offsets are scaled back to the guest's texels in the module, and an integer image that would need a smaller level is refused. Pitch images and volumes have no level addressing and are still refused.
- A plain 2D image taller than the device allows (no mipmaps, uncompressed rows) is folded into array layers of overlapping tiles (`wgsl::Fold`): Nintendo Switch Sports draws its text from a 1024x32768 `R8` glyph atlas, and every text draw fell back. Tiles share a row, so bilinear filtering and gathers read both rows from one tile and match the unfolded image exactly; rows past the end repeat the last, which is clamping. A repeating image (the atlas repeats) gets one more tile holding its last row and then its first, the only pair no other tile holds; the shader wraps the row before choosing a tile, so the sampler clamps v on every folded image. A mirrored v wrap is refused. Anything else past the device's limits is refused before `create_texture`: an invalid texture poisons every bind group made with it, and the draws after it are rejected.
- `tlds` fetches by integer coordinates in every encoding of Eden's `texture_load_swizzled.cpp` but 6 (multisample, which no sampled image here has), and refuses the register pairs Eden refuses as unaligned. The texture model holds level 0 only and the device is given one level, so a nonzero level register faults in `interp` and a level register other than `RZ` leaves the shader to the interpreter; a 1D fetch reads row 0 of a 2D image, since a 1D TIC is refused. An offset is added to the coordinates with wrapping, so a negative one past 0 is outside the image and reads zero on both. A folded image's fetch is checked by WGSL text and naga only.
- `tld4` and `tld4s` read `.AOFFI` as Eden does, signed six-bit fields at bits 0 and 8 (`tex`'s are four-bit nibbles at 0 and 4). A register offset moves the coordinates by whole texels before the gather in `interp` and in the WGSL (`texStep`, `1 / size` with a folded image's own height), because `textureGather` takes only a constant offset. `.PTP` gathers four times, each moved by its own offset, keeping that gather's texel. A cube gather picks its face as `sample_cube_with` does and reads a footprint over a face edge from the neighbouring face (`cube_neighbour`), as the device's seamless `textureGather` does; a footprint over a corner has no single neighbour and may differ. Not implemented: 1D, array-1D and 3D gathers (WebGPU has no `textureGather` form for them, and the texture model refuses 1D images), and an offset on a cube (Eden refuses it too).
- An integer image (`RGBA32Uint`) is read at the nearest texel on both renderers and bound with a non-filtering sampler of nearest filters, so `textureGather` of it is valid; its gathers and constant-offset samples carry the words as `bitcast<vec4<f32>>`. A swizzle other than the identity still refuses the draw.
- A held `ZF32` sampled smaller than it is held (rows laid out the same) copies the whole surface into the buffer and the sampled corner out of it, since depth copies take whole subresources. A depth surface last drawn as the crop a narrower colour target needs, and sampled larger with the same rows, is held at the sampled size first (`hold_at_sampled_size`, in `prepare`): the other size `switch_crop` keeps when that is the one sampled, else guest memory with the crops drawn over its corner, the current one last. Echoes of Wisdom draws its 1024x576 depth only as 256x144 and 512x288 crops and samples it whole. A surface held at two sizes keeps the other beside the current one; switching to a third merges the current into the earlier one when that is larger (`merge_crop`), since it alone may hold texels outside both: Tears of the Kingdom crops a 384x376 shadow cascade to 384x360 and then to 320x180, and dropping the 384x376 lost its last rows. Each layer of a sampled array is looked at so, and a larger size kept for a layer is switched back to where it holds the sampled image with the same rows, whose corner is then sampled: Tears of the Kingdom's post-processing draws beside its last 384x376 shadow cascade, still bound, crop it to 320x180, and the shadow map samples the cascades 376x376. A held surface stands in for a slice of a deep-block volume where it was drawn with the volume's block depth in its layout (`slice_layout`), or where the slice fits one GOB, where volume and surface addressing coincide; slice `z` is looked for where the volume puts it, not `z` layer strides along. Tears of the Kingdom binds each slice of its 64x64x64 and 32x32x32 `R8` volumes, 16 GOBs deep, as a target of its own one GOB along, and samples the volume after.
- Held surfaces sampled as textures must be copied from the device, not read stale from guest memory (Tomodachi Life's HDR reduction chain and cube faces). Float held depth (`ZF32`, and `ZF32_X24S8` whose stencil the device never holds) is copied via a buffer into `r32float` (Nintendo Switch Sports, Persona 5 Royal). Held `Z16` sampled as `R16` is drawn into the sampled colour format by `DEPTH_TO_COLOUR_WGSL` and its corner copied out, since no copy turns 16-bit depth into `r32float` (Breath of the Wild). A held `R32Float` colour surface sampled as a shadow map is drawn into it through `LOAD_DEPTH_WGSL`, as a padded depth corner is (`HeldLayer::ShadowCorner`; Breath of the Wild). Held `Z24S8` sampled as `S8D24` is converted into the `rg32float` image by `PACKED_DEPTH_WGSL` (`fs_held`: depth from the held surface, stencil from the uploaded words), which quantizes to 24 bits and decodes in integer arithmetic so the value is bit-identical to the rasterizer's (A Short Hike). Its copy is kept with the guest bytes it was made over (`HeldCopy::guest`), and reused while the texture cache hands out the same bytes and the held surface is unwritten: Echoes of Wisdom samples a 1280x720 one about ten times a frame, and remaking it each time was two thirds of bind time. A kept copy whose held layers were only written or added to takes just those layers (`stale_layers`), after the draws recorded before it: Breath of the Wild draws an 8-layer 1024x1024 `R16_UNORM` array a layer at a time, sampling it after every draw, and a fresh 32 MiB copy each time made 17780 copies by frame 700 where 1596 are made now. Padded surfaces sampled at their drawn size use the corner path when row layouts match (`same_rows`). A held colour surface sampled as another uncompressed format with the same bytes per texel is copied through a buffer (`HeldLayer::Bytes`), since texture copies need matching formats; sampled as `S8D24` words, its bytes are converted by `fs_words` as an upload of them would be. Echoes of Wisdom reads a `B8G8R8A8` target as `R32Uint`. Draws may sample their own target, so held layers are copied into a fresh texture; only a one-layer colour surface of the sampled size and format, unwidened, that the draw does not render to is bound directly (`directly_sampled`).
- Attachments must match in size: the pass covers the colour/depth intersection; a larger depth surface is cropped, and a larger colour target draws into a scratch texture copied back (WebGPU copies part of a colour texture but only whole depth textures).
- Colour outputs past 0 are attached beside output 0 (`Prepared::extra_colors`), each where it is bound, has a channel unmasked and is named by the fragment program's output map; the module declares an output per location up to the last attached one. What WebGPU cannot attach falls back: outputs of another size than output 0's, a later output without output 0, two attachments that overlap (WebGPU refuses a texture attached twice), multisampled routes, a colour scratch, outputs past `maxColorAttachmentBytesPerSample` (a rejected pipeline draws nothing), and outputs whose blend factors rewrite the shared constant differently.
- WebGPU details: no border address mode (wgpu web panics; the rasterizer also treats border as edge); strip pipelines must name the index format and non-strip pipelines must not, or the whole command buffer is rejected; Metal drops vertices whose stride overruns the buffer. The missing BGRA vertex format, per-texture swizzle and the y mirror are handled in the shader ([shader/wgsl/](gpu.md#shaderwgsl)).
- Maxwell has 32 vertex arrays and WebGPU guarantees 8 buffers, which is all Chrome offers. Mesa gives each attribute its own array, so Taisei draws from 11; binding them all made the device reject the pipeline and handed the session to the rasterizer. Past the device's count, `fit_vertex_buffers` interleaves the per-vertex arrays into one buffer (they share the draw's first vertex and count) and puts every zero-stride element (instanced arrays, the defaults) into a second. Draws within the count bind as before.
- `Renderer::report` nests timings to avoid duplicate "modules" keys (`JSON.parse` keeps only the last). Timings are written with one decimal place (`json::Decimals`) to keep the report short.

## `readback.rs`

- Readback is copy to staging, map, read: three steps that cannot happen in one call on the web. The map callback runs from the event loop, so state is an atomic polled by the next slice. Each ask for a frame's surfaces is a generation, at most two in flight, landed in order; a present waits on its generation.
- Memory that shaders write with stores or atomics is held on the device per descriptor address (`Space::globals`, sized by the size word NVN keeps after the descriptor's address, else to the end of its mapping, up to 8 MiB, rounded up to whole words so a buffer under a word still binds, as Minecraft's one-byte compute outputs are; the translator counts the size word as read so the bank upload reaches it) and asked back at every flush and present. Only the words that differ from the upload land, so a guest write elsewhere in the buffer in between survives. Written buffers are sub-allocations of one pool and may overlap. A later draw or launch that only reads inside one, touching no other, binds it and starts that many words in (`Global::base`, added in the module, since storage bindings take offsets only in steps of 256 bytes): Tears of the Kingdom reads 0x1c0 bytes into one. Any other read over one refuses until the flush, and so does the rasterizer's draw, which flushes first. A guest read of the memory before the next present sees the old words, as it does for held surfaces. A written buffer stays alive until its readback lands, so a draw in between can still read it. A fragment read through another descriptor of a buffer the same draw writes binds it writable too, since WebGPU refuses one buffer bound read-only beside a writable binding (Tears of the Kingdom); a vertex read of it, which cannot bind storage writable, reads a copy the draw makes before its pass (`GlobalUpload::snapshot`), as patches are copied, so it sees the buffer as the draws before it left it.
- Compute launches run on the device (`compute.rs`) when the translator takes the program; one it refuses (barriers, shared memory, packed `SR_TID`/`SR_NTID`, warp instructions without 32-lane subgroups) goes to the software dispatch after a flush, as every launch used to. The device route skips that flush: Persona 5 Royal launches about 40 a frame, each of which flushed every held surface. What a launch writes is a held global. A draw whose vertex array or constant banks overlap one copies the written bytes over the stale guest bytes on the device (`Patch`, before the pass; `patches_over`), from buffers still on their way back first so the newest wins. A patched constant buffer is the draw's own, so its bind group is not cached. One whose indices overlap refuses and flushes, since the indices also bound which vertices are uploaded; so does one whose vertex bytes were rearranged on the CPU. Past the vertex buffer limit, a patched array keeps a buffer of its own and only the others are folded (Echoes of Wisdom). `touches_nothing_held` counts held globals, so a copy or blit over them flushes too. A buffer a launch only reads is uploaded once and kept by address and length (`Space::inputs`, `compute_input`) until the guest writes its pages or the address maps to other pages.
- A launch samples textures as a draw does (`bind_texture`, shared with `bind_group`), through the QMD's banks and the compute engine's pools (`upload::TexturePools`). A null image sampled as a cube binds six transparent layers, since a cube view takes exactly six; Echoes of Wisdom's cubemap filter samples four. A null image's stand-in is kept without watched pages, since nothing writes it; uncached, it was a new texture and an unkept bind group every launch. A texture only `txq` reads (`TextureBinding::sized_only`) binds its guest-memory upload even over held layers, since no texel is read: the filter queries the face it stores to, which cannot be bound in place, and copied it off the device every launch to answer the size. A 2D `sust.p` with a full mask stores through a write-only storage texture: the image is held at its TIC's address like a render target, given `STORAGE_BINDING` (copied into a new texture if it was held without it) and marked written, so a later draw samples it from the device and a flush reads it back. Only WebGPU's guaranteed storage formats are taken (`convert::storage_format`); a null image stores into a texel of its own. `max_storage_textures_per_shader_stage` is raised to the adapter's, since the filter writes six faces and the default is four.
- `vote` and `shfl` in a compute program run on subgroups (`subgroupBallot`, `subgroupShuffle`) only when the adapter reports subgroups of exactly 32 lanes (`Gpu::warp_subgroups`), so each subgroup is one warp. Chrome on an Apple M4 reports 32 for both bounds; native wgpu reports 4 to 64 there, so host tools keep these launches in software. The lane is `subgroupExclusiveAdd(1u)` on entry, because naga refuses `subgroup_invocation_id` in a multi-dimensional workgroup. A read of a buffer a launch wrote is served from the held buffer itself when it names the same address.
- A held surface sampled as a texture that it does not cover exactly is copied into a texture of the sampled shape (`texture_over_held`). When the held layers cover every layer, guest memory is not read at all, and the copy is kept (`Space::held_copies`) until a source is written again: every write bumps `Held::writes`, and a copy is reused only while each source is the same texture at the same count. Persona 5 Royal samples two 1024x1024 shadow maps and its depth buffer in about 310 draws a frame; uploading and copying them per draw was 389 s of an 866 s native run to its menu, which now takes 455 s. A padded held colour surface sampled out of its top-left corner, clamped to the edge on both axes and only ever sampled (no gather, fetch or size query, which the translator records as `read_otherwise`), is bound in place instead (`crop_of_held`, `wgsl::Crop`): the module scales the coordinates to the surface and clamps them to the image's outermost texel centres, which filters exactly as clamping the copy would, nearest or linear. A repeating or mirrored wrap would filter in the padding at the edge, so those keep the copy.
- Depth row bytes are the device format's: `Z24S8` is 4 bytes in memory and 4 bytes of `f32` on the device; `ZF32_X24S8` is 8 and 4.
- A companion surface is resolved back into the held surface before the readback, so guest memory only sees the expanded form; its grid is stored because the register file has moved on by flush time.

## `builtin.rs`

- Depth uploads and shadow maps go through a fullscreen draw writing `frag_depth` from an `r32float` texture (`LOAD_DEPTH_WGSL`, one layer at a time), because a copy cannot write `depth32float`. `depth16unorm` could be copied but takes the same draw path so the two formats cannot diverge. A padded held `ZF32` or `Z16` shadow map layer is drawn by the same pass straight from the held depth texture, since a depth copy takes whole subresources; Breath of the Wild samples a three-layer 720x720 `Z16` shadow map out of surfaces held at 736x720. A shadow map whose layers are all `Z16` surfaces held at its size is copied into a `depth16unorm` map; when only some are, those are drawn by the same pass into the `depth32float` map the others are uploaded into, which holds 16-bit depths exactly (Tears of the Kingdom's cascades).
- The resample grid is a storage buffer, not a uniform: its tables are indexed by a runtime value, and a uniform array pads every element to 16 bytes.

## `tests.rs`
