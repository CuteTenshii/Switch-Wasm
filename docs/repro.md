# Reproducing and debugging

Every tool for getting a title to misbehave outside a browser, and what each one is for. AGENTS.md's *Commands* covers the build; this covers the runs.

Game images and keys (`.nro`, `.nsp`, `.xci`, `.nca`, `.keys`) are gitignored.

## Arguments

- Every tool is run as `cargo run --release -p switch-core --example <tool> -- <args>` and takes `--help`. Flags are parsed once, by `clap`, in `examples/common/mod.rs`; a tool declares only its own. Every tool that reads a container takes `<container> --keys <prod.keys> [--title-keys <title.keys>]`. The container may be an NSP, an XCI or a bare NCA, told apart by header (a bare NCA's header is encrypted, so its `.nca` name decides), and `--title-keys` may be left out when `prod.keys` or a bundled ticket already opens the title. A cartridge image's partitions are read as one file table without its `update` partition, a firmware bundle that is never the title.
- Tools that run a title to its frames (`boot_nsp`, `screenshot_title`, `screenshot_gpu`, `jit_bisect`, `shader_coverage`, `steady_state`) take `--firmware <dir>` naming a firmware dump whose NCAs `prod.keys` can open. Without the system data archives a title quits early on the one it mounts. NCAs that fail to open are skipped silently.
- Tools that take a `<target>` accept an `.nro` too, in which case `--keys` is left out; `--font <ttf>` replaces the shared font: `screenshot_title`, `screenshot_gpu`, `jit_bisect`, `frame_work`, `hotspots`, `jit_coverage`, `emit_difftest`.
- Every tool that boots a retail title boots it as the page does, with the NACP's save-data quota and add-on content base id, and takes `--update <update.nsp>` to run it patched, `--dlc <a.nsp>,<b.nsp>` to mount its add-on content (the page's pairing with no page in the way), and `--docked` to boot docked.
- The shared font is `web/font.ttf`, embedded in the wasm and in the tools, unless a tool is given `--font`; firmware fonts replace it when `--firmware` holds them.
- **The shared debugging knobs**, on `boot_nsp`, `boot_nx`, `screenshot_title` and `screenshot_gpu` alike: `--trap-write <addr>:<hex size>` and `--trap-read …` name the code that writes to or reads a region (`--trap-zero` includes zero writes, `--trap-last <n>` prints only the last n when the run stops), `--watch-pc <addr>[,...]` the code that reaches one (`--watch-regs`, `--watch-dump <spec>`, `--watch-last <n>`), and `--dump <base>[+<hex>][:<hex len>][,...]` hex-dumps guest memory wherever the run stopped, `<base>` being a register, `sp`, `pc` or an address (a leading `*` follows the pointer), as in `--dump x23+0x1830:0x40`.
- `--no-jit` disables translation for host tools (applied by `common::new_cpu`, as is `--no-vsync-throttle`). `--press <buttons>@<interval>` taps buttons periodically (e.g. `--press A+DOWN@300000000`), `--cores <n>` runs n more guest cores and `--no-draw` draws nothing.

## Tools

- `--example boot_nx <nro>`: shortest path to "does it halt cleanly". `--sd <dir>` copies a directory onto the SD card and, when the NRO is inside it, launches it from its SD path as the Files dialog does, so homebrew finds its data beside it; `--show <sd path>` prints an SD file when the run ends (a homebrew's own log). Takes the shared debugging knobs.
- `--example boot_nsp <container> --keys <prod.keys> [--max-steps <n>]`: the browser's Launch button, without a browser. `--shot <f.ppm>` writes the last presented frame; prefer it over reading `frames presented: 0` off a budget too short to reach one. `--stop-frame <n>` stops at a frame; `--profile <interval>` samples pcs by thread, page and caller.
- `--example screenshot_title <target> --out <out.ppm> [--frame <n>]`: the Nth *presented* frame, as in `screenshot_title hbmenu.nro --out out.ppm --frame 3`. Stops at the frame rather than at a step budget (homebrew also stops after 200M steps unless `--steps` says otherwise), which `boot_nsp --shot` cannot: a title needs billions of steps to reach its first, and picking a budget that lands after it is guesswork. Its own knobs are in [tooling.md](tooling.md).
- `--example dump_exefs <container> --keys <prod.keys> --out <dir>`: flat module images at their real load addresses plus a sorted `symbols.txt`. **This is what makes a retail backtrace readable.** `--example disasm_flat <file.bin> --base <base> --addr <addr> [--count <n>]` disassembles them there.
- `--example retail_trace <container> --keys <prod.keys> [--tail <n>] [--max-steps <n>]`: a ring buffer of the last N instructions, dumped on halt or fault. `--ring-from-step <n>` runs that many steps at full speed first, so a fault billions of steps in can be recorded in a minute. Set `--ring-min <pc>` past `rtld`, whose lazy-binding resolver would otherwise fill the whole ring; `--ring-from` and `--ring-stop-after` bound the recording. `--mark`/`--mark-dump` watch an API being called in order without recording the steps between.
- `--example jit_bisect <target> [--keys <prod.keys>] [--max-steps <n>] [--window <n>]`: the translator and the interpreter in lockstep, compared on registers, vector registers, flags, threads, console output and the framebuffer, and narrowed to the first slice they disagree on; the translator's work counters are printed when they agree. Exact until the first thread switch: after that the two engines interleave threads differently, both correctly, and a disagreement means only that.
- `node tools/browser_boot.mjs <container> --keys=… --title-keys=…`: the same boot in a real browser, sampling the run state and console every five seconds and saving it, with its periodic thread reports, the worker's output and the Rendering section.
- **Checking the WebGPU backend**: run `screenshot_title` and `switch-gpu`'s `screenshot_gpu` over the same frame and `cmp` the PPMs. `screenshot_gpu` takes `--press` as `boot_nsp` does and prints the Rendering panel's report (`rendering: {...}`) at the end: with `--web-limits --defer-readbacks` it falls back and latches where a browser would, so a browser's fallback reasons can be reproduced natively. `--only <i>` (or `<a>..<b>`) puts only those draws on the device, so a difference is exactly theirs.
- `--example opus_testvectors <dir> [--out <dir>]`: the Opus decoder against the RFC 8251 vectors (`opus_testvectors-rfc8251.tar.gz` from opus-codec.org), in stereo and mono. It reports the first packet of each vector whose range coder state disagrees with the encoder's, and writes `<name>.rs.dec` (and `<name>m.rs.dec`) into the out dir, `<dir>` by default, for `opus_compare` to score. `--example opus_difftest <dir>` does the same against a reference decode you generate yourself, which is how the output rates below 48 kHz and the multi-stream layouts get covered.

## Tracing

- Tracing is one mask of channels (`TRACE_IPC`, `TRACE_SVC`, `TRACE_WAIT`, `TRACE_NV`, `TRACE_GPU`, ...; the list is `switch_core::trace::ALL`). Host tools set it with `--trace ipc,svc,...` (a channel's name without `TRACE_`) in `common::parse`; the core reads no environment, so in the browser the console's log level decides: **Trace** turns every channel on, any other level turns them off. Trace is slow on a busy title and `TRACE_GPU` alone prints a line per method write; leave the level on Log unless a channel is needed.
- The channels to start from when a title misbehaves without faulting are the low-volume ones. `TRACE_FS` names every filesystem request, its path and the `Result` it was answered with (`2002-0001` is path-not-found), so a title looking for content it cannot find says so. `TRACE_IO` is the host side of the same reads: each range pulled out of the container. `TRACE_DRAW` is one line per draw and clear with the surface it lands in, on either backend; `TRACE_COPY` the DMA copies, inline uploads and 2D blits between them; and `TRACE_PRESENT` one line per frame scanned out. `TRACE_GPU` prints the draw, copy and present lines too, among every method write.

## In the browser

- `make wasm` once, then `bun run dev`.
- **Debug > Graphics > Rendering** shows which renderer is drawing and why, device totals, device time per frame, fallback reasons and device errors.
- **Debug > Graphics > Display** is the display path. Guest frames against canvas updates say how many presents were never painted; the timing table separates the worker's run slice from painting its newest frame on the canvas.
- **Debug > CPU > Translation** counts blocks translated, compiled to wasm, entered and chained.
