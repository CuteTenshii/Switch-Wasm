# Reproducing and debugging

The tools for making a title misbehave outside a browser. AGENTS.md's *Commands* covers the build; this covers the runs.

Game images and keys (`.nro`, `.nsp`, `.xci`, `.nca`, `.keys`) are gitignored.

## Arguments

- Every tool runs as `cargo run --release -p switch-core --example <tool> -- <args>` (`-p switch-gpu` for `screenshot`) and takes `--help`. `clap` parses flags once, in `examples/common/mod.rs`; a tool declares only its own. A tool that reads a container takes `<container> --keys <prod.keys> [--title-keys <title.keys>]`. The container is an NSP, an XCI or a bare NCA, told apart by header (a bare NCA's header is encrypted, so its `.nca` name decides); `--title-keys` can be left out when `prod.keys` or a bundled ticket already opens the title. A cartridge image's partitions are read as one file table without its `update` partition, a firmware bundle that is never the title.
- A tool that boots a retail title takes `--firmware <dir>`, a firmware dump whose NCAs `prod.keys` can open; NCAs that fail to open are skipped silently. Without the system data archives a title quits early on the one it mounts. An `.nro` takes it too, with `--keys`, so a homebrew that opens a library applet finds it installed.
- Tools that take a `<target>` accept an `.nro` too (then without `--keys`) and take `--font <ttf>`: `boot`, `screenshot`, `jit_bisect`, `frame_work`, `hotspots`, `jit_coverage`, `a32_jit_coverage`, `emit_difftest`.
- A tool that boots a retail title boots it as the page does, with the NACP's save-data quota and add-on content base id. `--update <update.nsp>` runs it patched, `--dlc <a.nsp>,<b.nsp>` mounts its add-on content (the page's pairing, no page in the way), and `--docked` boots docked.
- The shared font is `web/font.ttf`, embedded in the wasm and in the tools. `--font` replaces it, and so do firmware fonts when `--firmware` holds them.
- **The shared debugging knobs**, on `boot` and `screenshot`: `--trap-write <addr>:<hex size>` and `--trap-read …` name the code that writes to or reads a region (`--trap-zero` includes zero writes, `--trap-last <n>` prints only the last n when the run stops); `--watch-pc <addr>[,...]` names the code that reaches one (`--watch-regs`, `--watch-dump <spec>`, `--watch-last <n>`); `--dump <base>[+<hex>][:<hex len>][,...]` hex-dumps guest memory where the run stopped, `<base>` being a register, `sp`, `pc` or an address (a leading `*` follows the pointer), as in `--dump x23+0x1830:0x40`.
- `--no-jit` disables translation for host tools (applied by `common::new_cpu`, as is `--no-vsync-throttle`). A tool flattens only the flag groups in `examples/common/mod.rs` it honors, so `--help` lists no flag a run ignores: `Shared` (`--trace`, `--no-jit`, `--no-vsync-throttle`) everywhere; `Boot` (`--docked`, `--firmware`, `--update`, `--dlc`) on tools that boot a container; `Report` (`--dump-tex`, `--dump-wgsl`, `--dump-device-wgsl`, `--frame-times`) on tools that drive a run to frames; `Play` (`--press <buttons>@<interval>` taps buttons periodically, e.g. `--press A+DOWN@300000000`; `--cores <n>` runs n more guest cores; `--no-draw` and `--draw-from-frame <n>` draw nothing) on every tool that runs a title to frames except `jit_bisect`, which steps two machines in lockstep; `Shots` (`--shots-every`) on `screenshot`.

## Tools

- `--example boot <target> [--keys <prod.keys>] [--max-steps <n>]`: the browser's Launch button without a browser, for an `.nro` or a retail container (`--max-steps` defaults to unlimited for an `.nro`, 2 million for a title). For an `.nro` it is the shortest path to "does it halt cleanly". `--sd <dir>` copies a directory onto the SD card and, when the NRO is inside it, launches it from its SD path as the Files dialog does, so homebrew finds its data beside it; `--show <sd path>` prints an SD file when the run ends (a homebrew's own log). `--shot <f.ppm>` writes the last presented frame; prefer it to reading `frames=0` off a budget too short to reach one. `--stop-frame <n>` stops at a frame; `--profile <interval>` samples pcs by thread, page and caller.
- `-p switch-gpu --example screenshot <target> --out <out.ppm> [--frame <n>]`: the Nth *presented* frame, drawn as the browser draws it, as in `screenshot hbmenu.nro --out out.ppm --frame 3`. It stops at the frame, which `boot --shot` cannot: a title needs billions of steps to reach its first, and picking a budget that lands after it is guesswork. Its flags are in [tooling.md](tooling.md#cratesswitch-gpuexamplesscreenshotrs).
- `--example dump_exefs <container> --keys <prod.keys> --out <dir>`: flat module images at their real load addresses plus a sorted `symbols.txt`. **This is what makes a retail backtrace readable.** `--example disasm_flat <file.bin> --base <base> --addr <addr> [--count <n>]` disassembles them there.
- `--example retail_trace <container> --keys <prod.keys> [--tail <n>] [--max-steps <n>]`: a ring buffer of the last N instructions, dumped on halt or fault. `--ring-from-step <n>` runs that many steps at full speed first, so a fault billions of steps in is recorded in a minute. Set `--ring-min <pc>` past `rtld`, whose lazy-binding resolver would otherwise fill the ring; `--ring-from` and `--ring-stop-after` bound the recording. `--mark`/`--mark-dump` watch an API being called in order without recording the steps between.
- `--example jit_bisect <target> [--keys <prod.keys>] [--max-steps <n>] [--window <n>]`: the translator and the interpreter in lockstep, compared on registers, vector registers, flags, threads, console output and the framebuffer, and narrowed to the first slice they disagree on; when they agree it prints the translator's work counters. Exact until the first thread switch: after it the two engines interleave threads differently, both correctly, and a disagreement means only that.
- `node tools/browser_boot.mjs <container> --keys=… --title-keys=…`: the same boot in a real browser. Its flags are in [tooling.md](tooling.md#toolsbrowser_bootmjs).
- `python3 tools/thumb_difftest.py --cases N --seed S`, then `cargo run --release -p switch-core --example thumb_difftest`: random Thumb-2 snippets run under `qemu-system-arm` and the interpreter, reporting the registers and flags that differ. Needs `llvm-mc` and `llvm-objcopy`.
- **Checking the WebGPU backend**: run `screenshot` with and without `--software` over the same frame and `cmp` the PPMs; `--only <i>` narrows a difference to one draw. With `--web-limits --defer-readbacks` it reproduces a browser's fallback reasons natively ([tooling.md](tooling.md#cratesswitch-gpuexamplesscreenshotrs)).
- `--example opus_testvectors <dir> [--out <dir>]`: the Opus decoder against the RFC 8251 vectors (`opus_testvectors-rfc8251.tar.gz` from opus-codec.org), in stereo and mono. It reports the first packet of each vector whose range coder state disagrees with the encoder's, and writes `<name>.rs.dec` (and `<name>m.rs.dec`) into the out dir, `<dir>` by default, for `opus_compare` to score. `--example opus_difftest <dir>` does the same against a reference decode you generate yourself, which covers output rates below 48 kHz and the multi-stream layouts.

- Host tools start the console's clock at a fixed POSIX time (`common::new_cpu`), so a run repeats step for step; the page uses its own clock. At the epoch, `nnSdk`'s `clock_gettime(CLOCK_REALTIME)` fails and Minecraft dies of the `system_error` it throws.

## Tracing

- Tracing is one mask of channels (`TRACE_IPC`, `TRACE_SVC`, `TRACE_WAIT`, `TRACE_NV`, `TRACE_GPU`, ...; the list is `switch_core::trace::ALL`). Host tools set it with `--trace ipc,svc,...` (a channel's name without `TRACE_`) in `common::parse`. The core reads no environment, so in the browser the console's log level decides: **Trace** turns every channel on, any other level turns them off. Trace is slow on a busy title and `TRACE_GPU` alone prints a line per method write, so leave the level on Log unless a channel is needed.
- When a title misbehaves without faulting, start from the low-volume channels. `TRACE_FS` names every filesystem request, its path and the `Result` it got (`2002-0001` is path-not-found), so a title looking for content it cannot find says so. `TRACE_IO` is the host side of the same reads: each range pulled out of the container. `TRACE_DRAW` is one line per draw and clear with the surface it lands in, on either backend; `TRACE_COPY` the DMA copies, inline uploads and 2D blits between them; `TRACE_PRESENT` one line per frame scanned out. `TRACE_GPU` prints the draw, copy and present lines too, among every method write.

## In the browser

- `make wasm` once, then `bun run dev`.
- **Debug > Graphics > Rendering** shows which renderer is drawing and why, device totals, device time per frame, fallback reasons and device errors.
- **Debug > Graphics > Display** is the display path. Guest frames against canvas updates say how many presents were never painted; the timing table separates the worker's run slice from painting its newest frame on the canvas.
- **Debug > CPU > Translation** counts blocks translated, compiled to wasm, entered and chained.
