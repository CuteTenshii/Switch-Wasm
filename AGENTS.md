# AGENTS.md

Browser-oriented Nintendo Switch emulation core: an ARM64 (A64) integer interpreter plus PFS0/NSP, NCA, NRO and ELF parsers, compiled to WASM for the frontend.

## Commands

- `make all` — test + wasm + assets (the full pipeline).
- `make test` — `cargo test -p switch-core`. This is the only crate with tests (unit tests in each module + `crates/switch-core/tests/cpu_test.rs`).
- `make wasm` — `cargo build --target wasm32-unknown-unknown --release -p switch-wasm`.
- `make assets` — wasm + `cargo run -p make-demo`, then **copies the built `.wasm` into `web/assets/`**. The demo payload is regenerated by `tools/make-demo`.
- `make serve` — `python3 -m http.server 8000 --directory web` (after assets). Frontend is plain static JS; no bundler.
- Single test: `cargo test -p switch-core <test_name>`.
- `rustup target add wasm32-unknown-unknown` is required for the wasm build.

## Build pipeline traps

- The browser fetches `web/assets/switch_wasm.wasm` and `web/assets/demo.nro` as committed copies. Building `switch-wasm` alone does **not** refresh them — run `make assets`. `demo.nro` is regenerated from `crates/switch-core/src/demo.rs`, so changing the CPU or demo code requires `make assets` before manual browser testing.
- `make test` only covers `switch-core`; there are no tests for `switch-wasm` or `make-demo`.

## Architecture

- `crates/switch-core` — the emulation core, zero external deps. Modules: `cpu` (A64 interpreter), `mem` (sparse 4 GiB page table), `disasm`, `nsp`/`nca`/`nro`/`elf` (parsers), `demo` (hand-assembled demo NRO), `error`.
- `crates/switch-wasm` — `cdylib` for `wasm32-unknown-unknown`, exports a raw `extern "C"` ABI (no wasm-bindgen). Buffers cross the boundary via wasm linear memory (`switch_alloc`/`switch_free`); a handle is an index into a global session table. **No external deps by design** — JSON results are emitted by the hand-rolled `json_escape`/`write_into` helpers in `crates/switch-wasm/src/lib.rs`. Don't add serde/etc.
- `tools/make-demo` — host binary that writes `web/assets/demo.nro`.
- `web/main.js` — glue over the wasm ABI; also the source of truth for how the ABI is used.
- Emulated CPU addresses are `u32` (32-bit PC). Memory is a sparse page table (`PAGE_COUNT` computed in `u64` to survive wasm32 `usize` truncation); reads/writes to unmapped addresses fault with `Error::Cpu`.
- The demo framebuffer is memory-mapped at `FB_BASE = 0x3F00_0000` (640x360 RGBA) and input at `INPUT_ADDR = 0x3F10_0000`. Syscall ABI (`SyscallMode::Uart`): `SVC #0` halts, `#1` putchar(X0), `#2` putstr(X0). Commercial encrypted content is out of scope.

## Gotchas

- `cargo clippy` on the whole workspace **fails** in `switch-wasm` (deliberate raw-pointer `extern "C"` signatures trigger `not_unsafe_ptr_arg_deref`). `clippy`/`fmt` are not gating; `cargo fmt --check` is also not clean.
- `web/main.js` defines `finishRun` twice (lines ~214 and ~279); the second declaration shadows the first. Edit the later one.
- CPU test encodings in `tests/cpu_test.rs` and `demo.rs` are hand-assembled and cross-checked against QEMU's `a64.decode`; `demo_runs_and_prints_hex` asserts exact console output ending in `00000000000068ac`. A CPU change that breaks this fails the suite.
