Drop a homebrew .nro or a title .nsp / .xci to boot

…or open one. Everything runs locally in your browser.

A container is opened where it sits and read a range at a time, so a retail .nsp or cartridge image never has to fit in memory. It needs prod.keys, which the Files panel takes.

Keyboard: arrows = D-pad · Z/X = A/B · A/S = X/Y · Q/E = L/R · Enter = + · Shift = −. A connected gamepad is used automatically.

        Tracing
        off
      
      

        
        
Tracing caps each run slice so the log stays readable. A fault dumps the
          register snapshot and the last instructions into the console on its own.

        

          
          
        

      

    


    

      
        Diagnostic channels
        off
      
      

        
What the emulator says about itself while it runs, one switch per
          subsystem. These are the same channels a command-line run sets through the environment -
          hover a name for the variable that sets it. They are verbose by design: turn on the one
          that covers what is going wrong, not all of them.

        

      

    


    

      
        Threads
      
      

        
A title that has stopped and a title that is working look the same
          from outside. This says which thread is running, what each of the others is waiting on,
          and where it stopped - and lets you release them, which answers whether the stall is a
          thread nobody woke or a thread nobody started.

        

          
          
          
        

      

    


    

      
        Missing services
      
      

        
Everything this title has asked the console for and not been given,
          collected. Refused commands and commands answered with nothing behind the answer are
          listed apart, because they fail differently: the first stops the caller there, the second
          lets it carry on and fail somewhere else.

        

          
        

      

    


    

      
        Crash report
      
      

        
Everything an issue needs about this run in one file: the build, the
          title, the renderer and what it refused, the registers, the threads, the services that
          were missing, and the run-up to the fault. Take it while the run is still where it
          stopped - a reset is what loses it.

        

          
          
        

      

    


    

      
        Translation
        on
      
      

        
        
Guest code is compiled to pre-decoded blocks the first time it runs, so
          decoding is paid for once instead of on every instruction. Turn it off to run everything
          through the plain interpreter - the two execute identically, so a difference is a bug.

        

          
        

      

    


    

      
        Rendering
      
      

        
Which renderer is drawing, and why. A draw the device cannot take runs
          on the software rasterizer instead - and once enough of them have, the rasterizer keeps
          every frame after, however well the device is working. This says whether that has
          happened, what the fallbacks were, and where the device's own time went.
